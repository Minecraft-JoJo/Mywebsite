PROJECTS / 02 · TRAINING

自建 PyTorch 训练框架

PyTorch · ONNX · TensorBoard · PyYAML · SQLAlchemy + jose · PySide6 · CUDA / CPU

手写训练脚本的通病是每换一个数据集就复制一份 train.py：增强、断点续训、日志路径全散在循环里，第二次实验就开始对不上。这里要解决的是「换数据集不碰训练循环」——配置、数据、模型、循环四者只通过一个参数对象通信。代价写在同一句话里：任何一处字段改名都要同步四处。全套骨架 29 个 Python 文件 3,012 行。

形态
五层骨架（cfg / predata / model / train / logs），另带 users 鉴权与 main_ui 的 PySide6 面板

01任务与边界

这套骨架的产出不是某个模型，而是「换数据集只改配置」这件事本身。目录按职责分开：cfg/ 造参数对象，predata/ 给 Dataset 与 DataLoader，model/ 装配网络，train/ 是唯一写权重的地方，logs/ 收 TensorBoard 事件文件，load/ 负责把前四者组装成一个可训练对象。

它明确不做的事：

  • 不做分布式训练：单进程单卡，循环里没有 rank 与 all-reduce。
  • 不做超参搜索或实验管理服务，多组实验靠多次启动与时间戳目录。
  • 不做模型库（zoo）：model/build.py 按名字装配，没有预置权重仓库。
  • 不做服务端指标与上报，训练过程的唯一输出是日志文件与 checkpoint。
  • 不做数据标注工具：数据集进来之前已经是干净的。

边界换来的代价也很具体：四层之间只靠字段名约定，没有类型层，字段拼错要等运行到那一步才报。

03关键决策与取舍

三个决策分别管「层间怎么通信」「日志怎么隔离」「导出放在哪」。

D1 · 配置做成参数对象（cfg/build_cfg.py 的 setting 类）

理由训练、导出、推理拿到同一个对象，字段名一致；设备在构造时就选定 cuda 或 cpu，后面几层不再各自判断。

放弃dataclass 那层类型检查：字段拼错要等运行时才报，代价是调试一轮的时间。

D2 · 日志目录按启动时间戳切分

理由train/train_rnn.py 用 logs/tensorboard/{时间戳} 作 log_dir，同一份配置跑多次不互相覆盖，TensorBoard 里每条曲线都能追回一次启动。

放弃「一个实验一个固定目录」的整洁：目录数随实验数线性增长，清理靠手。

D3 · 导出独立成 train/out_onnx.py

理由训练进程不负责导出，checkpoint 是两者之间唯一的接口；导出失败不用重训，换个导出参数也不用碰训练脚本。

放弃训练结束自动导出的顺带便利：每次都要多执行一条命令。

04难点与解法

ONNX 导出对 checkpoint 结构敏感。torch.save 存的是字典而不是裸权重，键名一变导出就失败。做法是先 map_location="cpu" 载入，再 checkpoint.get("model_state_dict")，取不到直接抛 ValueError 并写明检查键名；然后 cpu()、eval()、no_grad 一条路导出，opset_version=12，dynamic_axes 只放开 batch 维，输入输出按名固定。

断点续训的轮次换算。循环写成 range(start_epoch, num_epochs + start_epoch)，屏幕上的轮次同源换算；两个 interrupted 权重路径分开写（train/train.py），避免中断时两份都不可用。load/load.py 负责把 cfg 装成 model、优化器、调度器与 start_epoch 四件套，循环本身不认识模型细节——这是「换数据集不碰循环」能成立的原因。

  • 三种模型形态各有一份循环：train.py、train_rnn.py、train_seqs.py；结构相同，差别在批数据形状与损失。
  • 参数对象里同时有 save_path（按模型名加时间戳拼出的 .pth）与 log_path（CSV 路径），两者来源不同，见第 6 节。

05代码走读

参数对象的全部作用是「把散落在脚本里的名字收成一份」。这一段来自 cfg/build_cfg.py，省略了与展示无关的字段。

# cfg/build_cfg.py — 训练 / 导出 / 推理共用的参数对象
class setting:
    def __init__(self, params, path):
        self.work_path = path
        self.device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
        self.batch_size = params["batchsize"]
        self.num_workers = params["num_workers"]
        self.epochs = params["epochs"]
        self.model_name = params["model"]
        self.lr = params["learning_rate"]

        save_path = f"{self.work_path}/save"
        self.save_path = f"{save_path}/{self.model_name}_{time.strftime('%Y_%m_%d_%H_%M_%S')}.pth"
        self.log_path = "./train_log/train.csv"

导出脚本只认 checkpoint，不认训练过程：载入失败与键名缺失都被挡在导出之前。

# train/out_onnx.py — 导出吃 checkpoint，不吃训练进程
checkpoint = torch.load(cfg.load_path, map_location="cpu")
load = LoadAll(cfg)
load.model_loader(cfg.model)

state_dict = checkpoint.get("model_state_dict")
if state_dict is None:
    raise ValueError("checkpoint 里没有 model_state_dict，检查 key 名称")

load.model.load_state_dict(state_dict)
load.model = load.model.cpu()
load.model.eval()

dummy_input = torch.randn(1, 3, 224, 224)
with torch.no_grad():
    torch.onnx.export(
        load.model, dummy_input, onnx_path,
        opset_version=12,
        input_names=["input"], output_names=["output"],
        dynamic_axes={"input": {0: "batch_size"}, "output": {0: "batch_size"}},
    )

06失败与下一步

这套骨架的债务是复制，不是设计。已知缺陷按影响排序：

  • 三份训练循环并存：train/train.py 252 行、train/train_rnn.py 305 行、train/train_seqs.py，改一个策略要改三处，改漏一处三个模型的曲线就不可比。
  • cfg/build_cfg.py 里留了一段写死的默认参数分支，由一个布尔量 selefUse 切换（拼写错误还在），默认值包含 epochs 60、lr 0.0003 和一条绝对数据集路径；这条分支绕过 params 入参，是「配置唯一」的最大例外。
  • 日志有两套口径：log_path 指向 ./train_log/train.csv（相对启动目录），TensorBoard 却写在 work_path 派生的时间戳目录里；换目录启动会得到一个位置漂移的 CSV。
  • users/ 的鉴权代码与训练框架同仓，main_ui/ 的 PySide6 面板也在里面；训练相关文件只占目录的一部分。
  • 没有单元测试；out_onnx.py 几乎是唯一带显式错误分支的脚本，其余靠运行时异常暴露。

下一步三件：把三份循环合并成「模型暴露 step 接口、循环只调用」的一处实现；删掉 selefUse 分支，让 params 成为唯一入口；把 log_path 改成由 work_path 派生。
