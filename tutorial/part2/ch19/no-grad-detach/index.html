no_grad、detach 与常见误用

上一课说 requires_grad=True 会建图。但图不是白建的：它占内存，还占时间。

很多地方根本不需要梯度。

一、哪些时候不需要梯度

场景为什么
评估 / 测试只算指标，不更新参数
推理 / 部署只做预测
数据预处理输入本来就不需要梯度
生成样本比如看模型输出了什么
打印 / 画图只是看数值

二、torch.no_grad()

一个上下文管理器，里面的运算一律不建图。

import torch, torch.nn as nn

model = nn.Linear(3, 1)

# 有梯度
pred = model(torch.randn(5, 3))
print(pred.requires_grad)      # True

# 无梯度
with torch.no_grad():
    pred = model(torch.randn(5, 3))
    print(pred.requires_grad)  # False

装饰器写法

@torch.no_grad()
def evaluate(model, loader):
    ...
    return correct / total

三、评估的标准写法

def evaluate(model, loader):
    model.eval()                    # 1. 切换到评估模式
    correct = 0
    total = 0

    with torch.no_grad():           # 2. 不建图
        for x, y in loader:
            out = model(x)
            correct += (out.argmax(1) == y).sum().item()
            total += y.size(0)

    return correct / total
model.eval() 和 no_grad 是两件事

model.eval()：改的是层的行为（Dropout 关闭、BatchNorm 用滑动统计量）。

no_grad()：改的是要不要建图。

两个都要做，缺一不可。只做 no_grad 不 eval，Dropout 还在随机丢神经元，结果每次不一样。

四、detach：把张量从图上摘下来

x = torch.randn(3, requires_grad=True)
y = x * 2

y.requires_grad      # True

z = y.detach()
z.requires_grad      # False
z.data_ptr() == y.data_ptr()    # True ← 共享同一份数据
no_graddetach
作用范围一段代码一个张量
典型场景整个评估循环只想把某个值取出来

最常见的用途：转 numpy

loss = criterion(pred, y)

loss.cpu().numpy()              # ✗ 报错
loss.detach().cpu().numpy()     # ✓
loss.item()                     # ✓ 标量直接取 Python 数字，最方便
.item() 比 detach 更常用

标量（loss、准确率）直接 .item() 拿 Python 数字，最简单。

只有需要整个数组时才 detach().cpu().numpy()。

五、三个常见误用

误用 1：评估时忘了 no_grad

# ✗ 慢，而且吃内存
def evaluate(model, loader):
    for x, y in loader:
        out = model(x)          # 建图了
        ...

短时间看不出问题。数据一大，或者评估次数一多，显存会持续上涨，最后 OOM。

误用 2：在 no_grad 里训练

with torch.no_grad():
    loss.backward()     # ✗ 报错：element 0 of tensors does not require grad

忘了图就没了梯度，backward() 无从算起。

误用 3：把 detach 用在不该用的地方

# ✗ 梯度在这里断了
h = model1(x).detach()
out = model2(h)         # model1 永远学不到东西

# ✓ 要让两部一起训，就不要 detach
h = model1(x)
out = model2(h)
detach 会切断梯度流

一旦 detach，反向传播走到这里就停了，前面的参数一个都不会更新。

而且不报错——模型照常训练，只是前半部分永远是随机初始化的样子。

这是"训练看起来正常但效果很差"的经典原因之一。

六、推断模式的第三种选择

torch.set_grad_enabled(False)   # 全局关掉
torch.set_grad_enabled(True)    # 打开

# 或者按条件
torch.set_grad_enabled(training)

no_grad() 本质上就是它的上下文管理器版本。平时用 no_grad 就行。

七、一句话总结

要做的事用什么
训练什么都不用加（默认建图）
评估 / 推理model.eval() + with torch.no_grad():
取一个数值.item()
转 numpy 数组.detach().cpu().numpy()
冻住一部分参数p.requires_grad = False
