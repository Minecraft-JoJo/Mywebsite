一张图片到底是什么

这一课在哪

前面几课一直在说「把图喂给网络」。但网络到底收到了什么？

这一课把一张图片拆到底：从你看到的图，到一堆数字，到张量的三个维度。

你看到的 vs 计算机拿到的

计算机不知道「这是数字 3」。它只知道一张表：28 行 × 28 列，每个格子里一个 0 到 255 的整数。

值看起来含义
0全黑这里没有笔画
255全白这里有笔画
128灰边缘，被笔画覆盖了一半
为什么是 0~255

一个字节 8 位，能表示 28=256 个值：0 到 255。

这是最省空间的存法。不是物理意义上的亮度， 而是「这个点有多亮」的一个约定。

一个像素其实是几个数

上面那个例子是灰度图——一个格子一个数。

彩色图不同：一个格子有三个数，分别是红、绿、蓝的亮度。

import numpy as np

# 一个 2×2 的彩色小图
pixel = np.array([
    [[255,   0,   0], [  0, 255,   0]],      # 红、绿
    [[  0,   0, 255], [255, 255, 255]],      # 蓝、白
])

print(pixel.shape)      # (2, 2, 3)
print(pixel[0, 0])      # [255   0   0]  纯红
print(pixel[1, 1])      # [255 255 255]  纯白
图形状一个像素几个数
灰度(H, W)1
彩色(H, W, 3)3（RGB）
带透明的彩色(H, W, 4)4（RGBA）

通道是什么

通道（channel）就是「同一张图有几种数值」。

通道数叫什么例子
1灰度MNIST 手写数字、X 光片
3RGB绝大多数照片
4RGBA带透明背景的 PNG
更多特征图网络中间层，不是原始图片
「通道」这个词在两种地方出现

① 输入图：3 通道 = RGB。这是物理世界的颜色。

② 网络中间层：64 通道、256 通道。 这不是颜色，是64 种不同的特征。

两个地方用同一个词，因为形状是一样的——都是「几张同尺寸的图叠在一起」。

从图片到张量

图片在磁盘上是一个文件。读到内存里变成一个数组。 喂给 PyTorch 之前，还要做三件事：

from torchvision import transforms
from PIL import Image

img = Image.open("cat.png")          # 1. 打开文件

print(img.size)                       # (宽, 高) —— 注意顺序！
print(img.mode)                       # "RGB"

to_tensor = transforms.ToTensor()
x = to_tensor(img)                    # 2. 变成张量

print(x.shape)                        # torch.Size([3, 高, 宽])
print(x.dtype)                        # torch.float32
print(x.min(), x.max())               # tensor(0.) tensor(1.)
步骤变了什么
打开文件(W, H) 的像素表，值 0~255
ToTensor通道提前：(3, H, W)；值除以 255
加 batch(B, 3, H, W)
两个最容易踩的坑

① 宽高顺序反了。PIL 的 size 是 (宽, 高)， PyTorch 的 shape 是 (通道, 高, 宽)。 一个 1920×1080 的图，PIL 说 (1920, 1080)， 张量是 (3, 1080, 1920)。

② 值域变了。ToTensor 会把 0~255 除以 255 变成 0~1。 自己直接 np.array(img) 拿到的是 0~255 的 uint8， 网络会训不动。

一次喂一批：四维张量

from torch.utils.data import DataLoader

loader = DataLoader(dataset, batch_size=32, shuffle=True)

for images, labels in loader:
    print(images.shape)      # torch.Size([32, 3, 128, 128])
    print(labels.shape)      # torch.Size([32])

维度含义这个例子里
第 0 维batch：几张图32
第 1 维通道3
第 2 维高128
第 3 维宽128

一个 batch 有多少个数？

print(32 * 3 * 128 * 128)      # 1,572,864

157 万个数。这还只是一张 batch。 float32 存下来是 6 MB。

这解释了第 26 章那个「参数爆炸」

一张 128×128 的彩色图就是 49,152 个输入。

接一层 1000 个输出的全连接，参数就是 49152imes1000=49,152,000。

这就是为什么图像任务不能直接用全连接——必须用卷积。

为什么图片适合卷积

回到那个 2×2 的小图，把它摊平成一维会怎样：

flat = pixel.reshape(-1)
print(flat)      # [255   0   0   0 255   0   0   0 255 255 255 255]

「红色」的 255 和「绿色」的 0 挨在一起，但它们毫无关系—— 它们本来在同一个像素里，是三个不同的分量。

拉平之后，「谁在谁旁边」这个信息全没了。 而图像的内容几乎全在「相邻」里。

保留成二维拉成一维
知道上下左右只知道前后顺序
相邻像素有关系相邻两个数可能毫无关系
能找边缘、纹理找不到

这一课留下的三个数

数值含义
值域0~255一个字节，存磁盘上
值域（张量）0~1ToTensor 除掉了 255
形状(B, C, H, W)通道在第二维
