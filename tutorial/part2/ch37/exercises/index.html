参考答案

一、算参数

① d=512, dff=2048

部件算式参数
多头注意力4 × (512×512 + 512)1,050,624
前馈网络(512×2048+2048) + (2048×512+512)2,099,712
两个 LayerNorm2 × 512 × 22,048
合计3,152,384

FFN 占了 67%，不是注意力。

② d=256, dff=1024

部件参数
多头注意力262,656
前馈网络525,568
两个 LayerNorm1,024
合计789,248

比值 3,152,384 / 789,248 ≈ 3.995——正好 4 倍。

因为所有矩阵都是二维的，维度减半，参数减到四分之一。

③ 6 层 → 2 层

6 层： 3,152,384 × 6 = 18,914,304
2 层： 3,152,384 × 2 =  6,304,768
少了：              12,609,536  （约 67%）

④ 头数 8 → 16

参数完全不变，还是 1,050,624。

因为 nn.Linear(512, 512) 是一个完整的大矩阵， 头数只决定怎么切，不决定有多少权重。

8 头每头 64 维，16 头每头 32 维——总数一样。

二、手推因果掩码
​1111​0111​0011​0001​​
问答
允许填 1 还是 01 表示允许，因为代码里写的是 masked_fill(mask == 0, -1e9)
−109 换成 0掩码失效。e0=1， softmax 会照常把权重分给未来的位置
编码器要不要因果掩码不要。源句是完整已知的， 每个位置都该看到全句
解码器跨注意力要不要不要因果掩码，但要 padding 掩码。源句没有「未来」可言，但要屏蔽补出来的词
三、找 bug

① 拆头忘了 transpose

# 错：8 个头夹在中间，矩阵乘只认最后两维，而且 Q@Q.T 变成了自乘
Q = self.w_q(x).view(B, T, self.n_heads, self.d_k)

# 对：
Q = self.w_q(x).view(B, T, self.n_heads, self.d_k).transpose(1, 2)

而且这里还写成了 Q @ Q.transpose(...)——这样算的是自相关，不是 Q 和 K 的点积。 必须用两个不同的张量。

② 除错了维度

math.sqrt(self.d_model)   # ✗ 512 的根号
math.sqrt(self.d_k)       # ✓ 64 的根号

参与点积的是每头 64 维的切片，方差是 64，所以除 sqrt(64)。

③ 拼回来没 transpose 回去

# 错：直接从 (B, h, T, dk) reshape，(B,h,T,dk) 的 h 和 T 还没换回来
out = Q.reshape(B, T, self.d_model)

# 对：先换回来，再合并 h 和 dk
out = Q.transpose(1, 2).reshape(B, T, self.d_model)

这个 bug 不报错，形状也对， 但八个头的内容被搅乱了——最难查的一类。

④ 嵌入忘了乘 sqrt(d)

x = self.src_embed(src) + self.pos(src)    # ✗ 位置编码会盖过词义
x = self.src_embed(src) * math.sqrt(self.d_model) + self.pos(src)   # ✓

词嵌入初始量级 ±1，位置编码也 ±1。 不缩放的话位置信息占了一半份量。

四、norm 放前面还是后面
问答
论文原文Post-LN，LN(x+F(x))
今天的大模型Pre-LN，GPT 系列基本都是
Pre-LN 的主干为什么更干净残差那条路 x→x+F(⋅) 上没有归一化打断，从输入一路通到输出
Post-LN 为什么依赖 warmup每个子层后面都要过 LN，主干被打断，深层梯度容易爆， 只能用极小的学习率先稳住
五、辨真假
#答案理由
1错编码器没有因果掩码。它的输入是完整源句， 每个位置都该看到全句。只有解码器自注意力才加
2错参数和头数无关。一个大矩阵切多少份，总数不变
3错37.10 课实测：2 层的 Transformer 在长句上还不如注意力 seq2seq。深是必要条件，不是充分条件
4对2,099,712 vs 1,050,624，正好两倍
5部分对它省的是重复的投影和 FFN； 注意力的打分本身还是要看全部 K，这部分省不掉
6错位置编码加在词嵌入上， 是进编码器之前，不是注意力之后
