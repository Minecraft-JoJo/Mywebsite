输出尺寸公式与感受野

上一课改了三个旋钮，看输出怎么变。这一课把它写成公式——搭网络时你要能事先算出来。

公式

输出边长 = ⌊(输入 + 2×padding − 核) / stride⌋ + 1

向下取整：除不尽时，多出来的那一格放不下核，直接丢掉

三个例子：

输入核padstride计算输出
28301(28−3)/1+126
28311(28+2−3)/1+128
28312(28+2−3)/2+114
28502(28−5)/2+112

最后一行值得注意：

(28 − 5) / 2 = 11.5   向下取整 = 11
11 + 1 = 12

第 13 个位置需要盖到第 24~28 列，但输入只有 0~27 —— 差一格，放不下，丢掉

“差一格”是常见困惑来源。你以为 28 会变成 13，实际是 12。

用代码验算

搭网络前先跑一遍，比事后查报错快：

import torch, torch.nn as nn

def size(n, k, p=0, s=1):
    return (n + 2 * p - k) // s + 1

cases = [
    (28, 3, 0, 1), (28, 3, 1, 1), (28, 3, 1, 2),
    (28, 5, 0, 2), (224, 7, 3, 2), (7, 7, 0, 1),
]
for n, k, p, s in cases:
    conv = nn.Conv2d(1, 1, k, padding=p, stride=s)
    real = conv(torch.randn(1, 1, n, n)).shape[-1]
    calc = size(n, k, p, s)
    print(f"{n:>4} 核{k} pad{p} stride{s} → 公式 {calc:>3}，实际 {real:>3} {'✓' if calc == real else '✗'}")

全部打勾才说明公式记对了。

搭网络时的实际用法

最常见的模式是：先把整个网络的尺寸链算一遍，再写代码。

输入 224×224×3
  Conv 3×3 pad1 → 224×224×64
  Conv 3×3 pad1 → 224×224×64
  MaxPool 2×2   → 112×112×64
  Conv 3×3 pad1 → 112×112×128
  MaxPool 2×2   →  56×56×128
  ...
  GlobalAvgPool →   1×1×128
  Linear        →  1000

这样列一遍，后面接 Linear 时才知道输入维度该写多少。 算错了就是那个经典报错：

RuntimeError: mat1 and mat2 shapes cannot be multiplied
    (64x25088 and 512x10)                  ↑ 这个数哪来的？

感受野：一个输出能看见多大范围

前面都在算形状。现在换一个完全不同的问题：

输出里的一个数，是由输入里多大一片算出来的？

这个“多大一片”，就叫感受野。

从一层开始数

一层 3×3 卷积，每个输出数由输入的 3×3 算出来。感受野 = 3。

两层呢？不要直接想 3+3=6，要一层一层数：

步问什么答
①第二层的 1 个输出，来自第一层的几输出？3×3 = 9 个
②第一层的这 9 个输出，在原图上是哪一片？它们的最左上那个看原图 3×3，最右下那个也看 3×3，两者相隔 2 格
③合起来覆盖多少？3 + 2 = 5

关键在那个“相隔 2 格”。

第一层相邻的两个输出，它们的窗口错开 1 格（因为 stride=1）。 第二层取 3×3 个第一层的输出，最左和最右相差 2 个位置， 在原图上就相差 2 格。

原图   ├─3 格─┤
              ├─3 格─┤        ← 第一层相邻输出，错开 1 格
              ├─3 格─┤
                  └──┘ 加起来：从第一个的左端到第三个的右端 = 5 格

所以规律是

每加一层 3×3 卷积，感受野 +2
1 层 → 3
2 层 → 5
3 层 → 7
n 层 → 2n + 1

加 2 而不是加 3，因为相邻窗口是重叠的——重叠的那部分不重复计算。

和 7×7 对比

结构感受野参数量（C→C）
3 层 3×37×73 × 9C² = 27C²
1 层 7×77×749C²
这是 VGG 的核心论证

感受野一样，参数只有 55%（27/49）。

而且三层意味着三次 ReLU，非线性更强。

这就是为什么 2014 年之后大卷积核几乎消失了。

有 stride 的时候会变

上面假设每层 stride 都是 1。一旦有 stride，后面每层的窗口就在原图上跨得更远，感受野增长会快得多。

这就是下一节要引入的 jump：往前走一步，在原始图上跨多远。

感受野的递推公式

考虑 stride 之后，公式是：

RF_0 = 1
RF_i = RF_{i−1} + (k_i − 1) × 前面所有 stride 的乘积

算一个例子：

layers = [("conv", 3, 1), ("conv", 3, 1), ("pool", 2, 2), ("conv", 3, 1)]

rf, jump = 1, 1
for name, k, s in layers:
    rf += (k - 1) * jump
    jump *= s
    print(f"{name} k={k} s={s}  →  RF = {rf}, jump = {jump}")

输出：

conv k=3 s=1  →  RF = 3,  jump = 1
conv k=3 s=1  →  RF = 5,  jump = 1
pool k=2 s=2  →  RF = 6,  jump = 2
conv k=3 s=1  →  RF = 10, jump = 2

最后一层的一个数，看到的是原图 10×10 的范围。

注意 jump 这个量——它是“往前走一步，在原始图上跨多远”。 有 stride 的时候它就不是 1 了。

为什么感受野重要

任务需要多大感受野
识别一个边缘几像素
识别一个数字整个 28×28
判断两张脸是不是同一个人覆盖整张脸
理解一句话的语义整句（这就是 Transformer 要解决的问题）

感受野不够大，模型就看不见需要的信息。这就是为什么深层网络的最后一层通常有几百像素的感受野——它要“看到整张图”。

感受野不是越大越好

太大反而会引入无关信息。分类任务里，最后通常接一个全局平均池化， 强制把整个图压成 1×1——那是“我确实要看全图”。

目标检测就不一样，要精确定位，感受野不能太粗。
