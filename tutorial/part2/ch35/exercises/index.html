拆开看 e=h=128 那一行：

部分计算参数

「想一想」的答案：

隐层 128 → 256，总参数从 1,609,144 涨到 3,608,504，约 2.24 倍。

但两个 RNN 从 99,072 涨到 393,984，是3.98 倍，基本就是 4 倍。

因为 RNN 参数是隐层的平方，而 embedding 是线性的。

embedding 占了大部分，所以总参数的涨幅被稀释到 2.5 倍。

n译文的 n-gram对上几个p_n

注意 2-gram 那行要仔细数。参考的 2-gram 是：我喜欢、喜欢吃、欢吃香、吃香蕉。 译文的 2-gram 里能对上的：我喜欢、喜欢吃……

实际跑出来是 3 个——因为「欢吃苹」不对，但「吃苹果」的「吃」 在参考里也有对应位置。

手算 BLEU 极容易错

上面这段我第一版就数错了：写成 2 个，实际是 3 个。

n-gram 的匹配要按多重集交集算（每个 gram 取 min 出现次数）， 靠眼睛数很容易漏。

答案永远以代码输出为准。

BP：译文 6 字，参考 6 字，长度相同 → BP = 1.0。

几何平均：

40.6667×0.6000×0.5000×0.3333​=0.5081

BLEU = 1.0 × 0.5081 = 50.81。

用代码验一遍：

import math
from collections import Counter

def bleu(hyp, ref, N=4):
    ps = []
    for k in range(1, N + 1):
        hg = Counter(tuple(hyp[i:i+k]) for i in range(len(hyp) - k + 1))
        rg = Counter(tuple(ref[i:i+k]) for i in range(len(ref) - k + 1))
        m = sum(min(c, rg[g]) for g, c in hg.items())
        t = sum(hg.values())
        ps.append((m + 1) / (t + 1) if m == 0 else m / t)

    log_sum = sum(math.log(p) for p in ps) / N
    bp = 1.0 if len(hyp) > len(ref) else math.exp(1 - len(ref) / len(hyp))
    return bp * math.exp(log_sum)

print(bleu(list("我喜欢吃苹果"), list("我喜欢吃香蕉")))   # 0.5081
只有最后一个字不同，BLEU 却只有 50

人看这两句：几乎一样，就一个水果的区别。

BLEU 给 50 分——因为长度短，4-gram 里只要有一个字不同就全灭。

这正好说明 BLEU 的一个毛病：短句上特别敏感。

三、判断推理策略
#选理由
1束搜索离线批量，不赶时间；质量优先
2贪心要快，宁可差一点
3采样要的是多样性，束搜索会给出 5 条几乎一样的
4束搜索可复现（贪心也可复现，但束搜索效果更好）

第 3 题是关键：束搜索优化的是「整句概率最高」， 所以 5 条候选往往高度相似。要多样性必须用采样。

四、找 bug
#问题后果
①标签没右移（写成 tgt[:, :-1]）模型学成「原样复制输入」，损失掉得飞快，推理时一句都翻不出
②没有 ignore_index模型花力气学「在 padding 位置输出 padding」， 浪费容量
③训练时用了自己的预测变成「无 teacher forcing」，错误累积， 训练早期几乎学不动
④LSTM 的 c 没传c_n 丢了，解码器初始记忆是 0。 不报错，但效果明显差

④ 的正确写法：

_, (h_n, c_n) = model.encoder(src, src_len)
state = (h_n.squeeze(0), c_n.squeeze(0))     # 两个都传
