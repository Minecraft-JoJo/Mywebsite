训练时怎么喂解码器

这一课在哪

上一课搭好了结构。但留了一个问题没答：

训练时，解码器每一步的输入从哪来？

有两个选择，差别很大。

两种做法

做法 A：自己猜的做法 B：标准答案
第 1 步输入<bos><bos>
第 2 步输入模型自己猜的第 1 个词标准答案的第 1 个词
第 3 步输入模型自己猜的第 2 个词标准答案的第 2 个词
和推理一致吗一致不一致
能并行吗不能不能（循环还是要跑）

做法 B 叫 teacher forcing——训练时把正确答案喂进去，像老师扶着走。

实际训练全都用 B。为什么？

用 A 会怎样

看一个具体的例子。目标译文是「我不想去」。

第 1 步：输入 <bos>       → 猜「我」     ✓
第 2 步：输入「我」      → 猜「不」     ✓
第 3 步：输入「不」      → 猜「想」     ✓
第 4 步：输入「想」      → 猜「去」     ✓

看起来没问题。但如果第 1 步就猜错了呢：

第 1 步：输入 <bos>       → 猜「他」     ✗
第 2 步：输入「他」      → 猜「不」
第 3 步：输入「不」      → 猜「想」
第 4 步：输入「想」      → 猜「去」

模型后面几步其实都猜对了，但因为第 1 步错了， 整句的损失变得很大。

这叫「错误累积」

用 A 的话，一个错会污染后面所有的输入。

训练早期模型几乎每步都错，于是每一步都要在「前面已经错了」的 状态下学习——学得很混乱。

更糟的是，梯度要穿过很长的时间链才能到第 1 步，而那时 信息早被污染得没意义了。

用 B 好在哪

#好处
①每一步都在正确的前提下学—— 第 3 步只需学会「给定前两个正确的词，第 3 个该是什么」
②错误不会累积，训练稳定
③每一步都能立即算出损失并回传，不用等整句生成完
# 训练时：直接用标准答案
word = tgt[:, t]

# 推理时：用自己刚猜的
word = logits.argmax(dim=1)

这两行的差别，就是训练和推理的全部差别。

但 B 有个代价

训练时模型永远看到的是正确的前文， 推理时看到的却是自己写的前文。

这个不一致会带来一个具体的毛病：

「曝光偏差」（exposure bias）

模型在训练中从来没有见过自己写错的样子。

推理时一旦写错一个词，它面对的是一个训练时从没出现过的状态，于是更容易继续错下去。

表现就是：单独看每一步都合理，连起来整句却跑偏了， 甚至重复同一个词直到撞上长度上限。

怎么缓解

办法怎么做代价
scheduled sampling训练时以一定概率喂模型自己猜的词， 这个概率随训练逐渐升高实现复杂，效果不稳定
beam search推理时同时保留几条候选，别一条走到底慢，但稳（35.7 讲）
就用 teacher forcing接受它，靠其他手段兜底最常用

绝大多数实现就是老老实实用 teacher forcing。它的好处远大于代价。

训练里的一个细节：标签要错一位

这是最容易写错的地方。

目标句：   <bos>  我  不  想  去  <eos>

解码器输入：  <bos>  我  不  想  去
解码器标签：   我    不  想  去  <eos>
              ↑ 全部左移一位

输入是「前面有什么」，标签是「下一个该是什么」。所以两者天然差一位。

out = model(src, src_len, tgt)      # out:  (B, L-1, V)
gold = tgt[:, 1:]                        # gold: (B, L-1)

loss = loss_fn(
    out.reshape(-1, vocab_size),
    gold.reshape(-1),
)
差一位写错的后果

如果写成 gold = tgt[:, :-1]（没右移）， 就变成「预测输入本身」——模型只需学会原样复制。

损失会掉得很快，看起来训练很成功，但推理时一个词都翻不出来。

这个 bug 很难发现，因为训练指标一切正常。

padding 也要屏蔽

一个 batch 里的句子补齐后，短句后面全是 <pad>（编号 0）。

这些位置不该算损失——它们是补出来的，不是要预测的内容。

loss_fn = nn.CrossEntropyLoss(ignore_index=0)      # 0 = <pad>

不加 ignore_index，模型会花很大力气去学「输出 pad」， 因为 padding 在数据里占的比例很高。

完整的训练一步

for src, tgt, src_len, tgt_len in train_loader:
    src = src.to(device)
    tgt = tgt.to(device)

    out = model(src, src_len, tgt)              # (B, L-1, V)
    gold = tgt[:, 1:]                           # (B, L-1)

    loss = loss_fn(
        out.reshape(-1, vocab_size),
        gold.reshape(-1),
    )

    optimizer.zero_grad()
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()

四行里三个坑，都在上面标出来了：

行坑
tgt[:, 1:]错一位
ignore_index=0padding 不能算损失
clip_grad_norm_解码器也是循环网络，梯度会爆

这一课留下的三个数

数值含义
训练用标准答案teacher forcing
推理用自己猜的自回归
标签偏移1 位tgt[:, 1:]
