AlexNet：特征不该由人设计

这一课在哪

上一章的 LeNet 是 1989 年的，认手写数字能到 94%。 之后整整 23 年，卷积网络几乎没人提。

2012 年 AlexNet 出现，把 ImageNet 的错误率从 26.2% 打到 15.3%。 这一课讲它到底改变了什么。

2012 年之前，大家是怎么做的

特征是手工设计的。

研究者写一个函数，从图里算出某种「特征」，然后把这些数喂给分类器。 有名的几个：

方法算的是什么
SIFT关键点周围的梯度方向直方图
HOG局部区域的梯度方向分布
SURFSIFT 的加速版
bags of visual words把局部特征聚成「视觉单词」再统计

这些东西的手感是：你先想清楚「什么是有用的」，再把它写成公式。

当年的潮流就是设计新特征函数、改进结果、发论文。

这条路的天花板在哪

你能想到的特征是有限的。而且换一个任务，特征就得重设计。

更要命的是——你怎么知道自己漏掉了什么？

另一派人的想法

有一批人不这么干。Yann LeCun、Geoff Hinton、Yoshua Bengio、Andrew Ng……

他们的主张只有一句：特征本身应该被学习。

手工特征学习特征
特征从哪来人写公式梯度下降自己找
换任务重新设计重新训练
上限人的想象力数据和算力

这个想法 1990 年代就有了（LeNet 就是），但一直没赢。

学出来的特征长什么样

AlexNet 训练完之后，把它的权重画出来，发现了一件有意思的事：

层学到了什么
最底层和传统滤波器几乎一样——边缘、颜色、纹理
更高层眼睛、鼻子、草叶这类部件
再高整个人、飞机、狗、飞盘
最后能用来区分类别的综合表示
最底层「一样」这件事说明了什么

人手工设计的 SIFT、HOG，本质上也就是在找边缘和梯度方向。

网络自己学出来的第一层，殊途同归。

差别在后面：人能设计出第一层的特征，设计不出第四层的。

那为什么是 2012 年

想法 1990 年就有，结构 1989 年就有。差的是两样东西。

缺的第一样：数据

之前2009 年之后
数据集UCI 的几个公开集ImageNet
规模几百到几千张100 万张，1000 类
怎么来的小团队自己拍谷歌图片搜索预筛 + 亚马逊众包标注

李飞飞的小组做的。用谷歌图片搜索对每一类做预筛， 再用亚马逊众包逐张标类别。

这种规模之前没有过。

为什么数据是决定性的

手工特征在几百张图上就行——因为它不需要「学」。

而学习需要样本。参数越多，需要的样本越多。

没有 100 万张图，6110 万参数的 AlexNet 只会过拟合到没法用。

缺的第二样：显卡

这是最反直觉的一条。为什么 GPU 比 CPU 快？

不是因为它每个核更快——恰恰相反，GPU 的单个核更慢。

CPUGPU
核心数笔记本最多 4，服务器很少超过 64100 ~ 1000 个
单核性能强（高主频、大缓存、分支预测）弱（有时低于 1GHz）
浮点性能不到 1 TFlops312 TFlops（Ampere）
内存带宽1×10×

为什么「核多但每个更弱」反而赢？做一个简单的算术：

一个 GPU 核的速度是 CPU 的 1/4
但可以用 16 个 GPU 核代替 1 个 CPU 核

综合性能 = 16 × (1/4) = CPU 的 4 倍

再加上 GPU 更省电（简单内核），内存带宽高 10 倍。

为什么这事对深度学习特别重要

深度学习的计算有个特点：大量重复的、简单的矩阵乘法。

这正好是 GPU 擅长的——上千个核同时算不同的乘法，不需要什么分支预测。

而 CPU 那些强大的功能（分支预测、大缓存）在这里完全用不上。

AlexNet 用了两块 GTX 580，各 3GB 显存， 因为一块装不下——模型太大，他们把网络拆成两半分别放在两张卡上。

所以 AlexNet 到底改了什么

改动为什么
把网络做深做大数据够了，撑得起
激活从 sigmoid 换成 ReLUsigmoid 导数最大 0.25，深层传不回去
用 Dropout 控制全连接层LeNet 只用了权重衰减，不够
数据增强（翻转、裁切、变色）等价于把样本量变大
用 两块 GPU 训一块装不下
结构上其实没什么新东西

卷积、池化、全连接——LeNet 全都做过。

AlexNet 真正做的，是在一个 100 万张图的问题上，把 LeNet 的思路放大 1000 倍， 顺便解决了放大之后暴露的工程问题。

而「放大」本身，靠的是数据 + 显卡。

为什么第一个卷积是 11×11

LeNet 用 5×5，AlexNet 一上来就用 11×11。为什么？

因为图变大了 10 倍

MNIST 是 28×28，ImageNet 是 224×224 甚至更大。

用 5×5 的核在 224×224 的图上扫，第一层只能看到 5/224 = 2% 的宽度—— 连一条完整的边都判断不了。

11×11 是为了让第一层看得够宽， 同时用 stride=4 把 224 快速压到 55，省算力。

第二层降到 5×5，后面全是 3×3——越往后核越小。

这个「越来越小」看着随意，但下一课 VGG 会把它变成一条规矩。
