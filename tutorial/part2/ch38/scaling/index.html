七年，一万倍。而骨架基本没动——上一课那张表就是全部改动。

这件事本身就很反常

历史上很少有架构能撑住四个数量级的放大还保持不变。

RNN 加两个数量级就崩了（第 34.1 课的梯度问题）。 Transformer 撑住了——因为它的路径长度是 O(1)。

第 37.1 课那张「三种架构对比表」，真正的价值在这里才显现。

Scaling Law：为什么敢一直放大

2020 年有人发现：loss 和规模之间是幂律关系。

L(N)∝N−α

N 是参数量，α 大约是 0.07～0.1。

翻成大白话：

参数涨loss 大约降
10 倍15%～20%
100 倍30%～35%

看着不多，但这是可预测的。

可预测 = 敢投钱

在这之前，谁也不知道把模型放大一倍会怎样——可能变好，可能崩。

Scaling Law 让「多花十倍算力能换来多少提升」变成一个可以算的问题。

这是大模型军备竞赛的技术前提。

但光堆参数不够

后来的研究发现：参数和训练数据要同比例涨。

说法建议
早期（2020）参数优先，数据少一点没关系
现在每个参数配 20 个 token 左右

Llama 3 405B 用了 15 万亿 token—— 平均每个参数 37 个 token，比「教科书建议」还多。

为什么？因为高质量数据快用完了。

互联网上的文本是有限的。当模型大到一定程度，不是算力不够，是没东西喂了。

今天的模型怎么「不那么贵」

既然数据有限、算力有限，就得想办法提高效率。

① MoE：只激活一部分

把前馈网络拆成很多个「专家」，每个 token 只走其中两个。

普通前馈：  每个 token 走同一个 4d 网络
MoE：       每个 token 走 8 个专家里的 2 个
总参数每个 token 实际用
DeepSeek-V3671B37B
Mixtral 8x7B47B13B
MoE 的精髓

参数量（知识容量）很大，但每次计算只用一小部分（省算力）。

671B 的模型，跑起来的速度和 37B 的差不多， 但能力接近一个完整的 671B 稠密模型。

代价是显存——所有专家都得装进显卡。

② 更长的上下文

2017 年论文处理的是几十个词。今天动辄几十万 token。

这件事之所以可能，靠的正是第 37.11 课那个 KV 缓存和 RoPE 的外推能力。

③ 更好的数据

今天各家花在数据清洗和配比上的力气，不比调模型少。

代码、数学、多语言、教科书——按什么比例混，直接影响最终能力。

三段式训练

今天训一个大模型，不是「训一次」，是三段：

阶段做什么数据量目标
① 预训练预测下一个词万亿 token学会语言和世界知识
② 指令微调问答对，学「听指令」几十万条从「续写」变成「回答」
③ 对齐人类偏好（RLHF / DPO）几万条有用、无害、诚实
三个阶段的量级差得离谱

预训练 万亿 token，指令微调几十万条， 对齐几万条。

差了七八个数量级。

预训练决定能力上限，后两步只决定「怎么用出来」。

对齐为什么需要

预训练完的模型只会一件事：接着往下写。

问：中国的首都是哪里？
预训练模型：中国的首都是哪里？这是一个常见的问题。很多人……

它把问题当成文章的开头，接着写下去——技术上完全正确， 但不是用户要的。

指令微调就是教它：看到问题，该回答，不该续写。

为什么不是「一直放大」

瓶颈现状
数据高质量文本接近用尽
算力训练一次要几万张卡跑几个月
电力单个数据中心的供电成了硬约束
推理成本模型越大，服务一个用户越贵

所以 2024 年之后，重点从「更大」转向了「更高效」—— MoE、蒸馏、量化、更好的数据配比。
