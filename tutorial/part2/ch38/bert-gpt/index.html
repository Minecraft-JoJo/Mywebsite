删掉一半：BERT 与 GPT

这一课在哪

第 37 章最后，你手上是一个完整的模型： 六层编码器 + 六层解码器。

现在问一件事，问完两条路线就分家了。

如果只留一半呢？

留编码器：BERT

把解码器整个删掉，只留编码器加一个输出层：

class BERT(nn.Module):
    def __init__(self, vocab, d_model=512, n_layers=6):
        super().__init__()
        self.embed = nn.Embedding(vocab, d_model)
        self.pos = PositionalEncoding(d_model)
        # 只有编码器
        self.layers = nn.ModuleList([EncoderLayer(d_model) for _ in range(n_layers)])
        # 输出层：每个位置预测一个词
        self.fc = nn.Linear(d_model, vocab)

    def forward(self, x):
        h = self.pos(self.embed(x))
        # 没有因果掩码——整句都能看
        for layer in self.layers:
            h = layer(h)
        return self.fc(h)      # (B, T, vocab)

它一次处理整句，每个位置都能看到所有其它位置。

那用它干什么

没有解码器就不能生成——没有「一步接一步」的机制。

所以 BERT 的用法是填空：

输入   我 [MASK] 欢 你
输出   预测 [MASK] 位置是什么词 → 「喜」

训练时随机遮掉 15% 的词，让模型猜。猜得准，说明它理解上下文。

理解能力可以直接拿去用：分类、情感判断、抽取实体、判断两句话是否相似。

留解码器：GPT

删掉编码器，只留解码器：

class GPT(nn.Module):
    def __init__(self, vocab, d_model=512, n_layers=6):
        super().__init__()
        self.embed = nn.Embedding(vocab, d_model)
        self.pos = PositionalEncoding(d_model)
        # 只有解码器——但不需要跨注意力了
        self.layers = nn.ModuleList([DecoderLayerNoCross(d_model) for _ in range(n_layers)])
        self.fc = nn.Linear(d_model, vocab)

    def forward(self, x):
        h = self.pos(self.embed(x))
        # 必须加因果掩码
        mask = causal_mask(x.size(1))
        for layer in self.layers:
            h = layer(h, mask)
        return self.fc(h)

它看起来和 BERT 很像，只多了一个因果掩码。

但这一点差别决定了一切：每个位置只能看前面的， 所以它的输出可以当作「下一个词的预测」。

那用它干什么

输入   今天 天气 真
输出   预测下一个词 → 「好」
      接上去再跑 → 「今天 天气 真 好」

能生成。这就是今天所有大模型在做的事。

两条路线摆一起

BERT（只留编码器）GPT（只留解码器）
结构编码器 + 输出层解码器 + 输出层
因果掩码不要必须要
每个位置能看整句它前面的
训练目标填空预测下一个词
能不能生成不能能
擅长理解生成
代表BERT、RoBERTaGPT、Llama、Qwen
代码上看，它们差得极少

有一份教学实现里，BERT 这个类是直接继承 GPT 的：

class BERT(GPT):
    def __init__(self, ...):
        super().__init__(...)
        # 只改了两处：去掉因果掩码、换训练目标

两个听起来完全不同的模型，骨架是同一个。

为什么最后是 GPT 赢了

2018 年 BERT 出来的时候，它在各种理解任务上全面碾压。 当时没人觉得生成这条路能赢。

转折点在两件事上。

① 填空只能做理解，预测下一个词能顺带做理解

想让模型「预测下一个词」预测得准，它必须理解上下文—— 语法、事实、逻辑，一样都躲不掉。

生成是更难的任务，学会了生成，理解是副产品。

反过来不成立：会填空的模型不会写文章。

② 数据形态

需要什么数据互联网上有多少
BERT句子（不需要标注）多
GPT任何连续的文本几乎无限

BERT 要「一句一句」的语料，得先切句、清洗。 GPT 只要把整本书连起来就能训——网页、代码、书，全都能用。

当模型大到几十亿参数时，数据量成了瓶颈。GPT 这条路能吃到更多数据，所以能长得更大。

一句话总结这场分家

BERT 把模型做成了「理解器」，GPT 把模型做成了「通用预测器」。

后者看起来更笨——只会接着往下写。

但它能吃掉全世界所有的文本，规模一上去，什么都学会了。

回头看第 37 章那个模型

你手写的那个 Transformer 里，两个部件都在：

你的代码被谁拿走了
self.encoderBERT
self.decoderGPT
DecoderLayer 的跨注意力两边都不要——因为只留一半，没有「另一半」可以看

翻译任务需要两个部件配合，所以它们都得留。 但大多数任务不需要，删掉一半反而更好训。

还有第三条路

不删，两个都留——就是你在第 37 章做的编码器-解码器模型。

T5、BART 走的就是这条。做翻译、摘要这类「输入一段、输出另一段」的任务时它更合适。

只是今天不是主流。原因和上面一样：吃不到那么多数据。
