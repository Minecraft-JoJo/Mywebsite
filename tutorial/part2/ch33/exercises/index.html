import csv
from collections import Counter

PAD, UNK, BOS, EOS = "<pad>", "<unk>", "<bos>", "<eos>"

def read_tsv(path):
    out = []
    with open(path, encoding="utf-8") as f:
        r = csv.reader(f, delimiter="\t", quoting=csv.QUOTE_NONE)
        next(r)
        for row in r:
            if len(row) >= 2 and row[0].strip() in ("0", "1") and row[1].strip():
                out.append(row[1].strip())
    return out

texts = read_tsv("D:/main/AIchallenger2017/sentiment/train.tsv")
counter = Counter()
for t in texts:
    counter.update(t)

for min_freq, max_size in [(1, 10000), (2, 10000), (5, 10000), (2, 2000)]:
    v = 4
    for ch, f in counter.most_common():
        if f < min_freq or v >= max_size:
            break
        v += 1
    emb = v * 128
    total = emb + 64 * 128 + 64 * 64 + 128 + 130
    print(f"min_freq={min_freq} max={max_size}  V={v}  emb={emb:,}  占比={100*emb/total:.1f}%")

四、辨真假

#说法对 / 错 + 理由
1RNN 的参数量随句子长度增加
2梯度裁剪会改变梯度的方向
3用了 packing 就不需要传 lengths 了
4第 1 轮 train 准确率低于 dev 是正常的
5保存模型时词表可以不用存

参考答案

一、词表大小
设置Vembedding占比
min_freq=1约 6000768,00097.8%
min_freq=23,660468,48097.4%
min_freq=5约 2500320,00096.2%
max_size=20002,000256,00095.3%

实测 min_freq=2 得到的词表是 3,660， 模型总参数 481,026。

embedding 永远占 95% 以上——所以词表是第一个要调的旋钮。

二、该不该 packing
#要用吗理由
1不用长度全一样，没有 padding
2要用典型情况，padding 会污染 h_n
3建议用不用也不会错，但 padding 的位置仍然参与计算，浪费算力；而且 out 在 padding 位置的值是垃圾
4不用一个样本就是一个长度，没有 padding

规则：只要 batch 里长度不一样，就用。

三、三个错
#错在哪后果
①zero_grad 放在 step 之后勉强能跑，但语义反了。 正确顺序是 zero → backward → step
②没有梯度裁剪RNN 的梯度会爆，loss 可能突然变 NaN
③没有 zero_grad梯度会一直累加，几步之后爆炸。 这是最常见的 RNN 训练 bug

① 其实也能跑（因为第一轮之后 grad 是干净的）， 但代码语义不对，容易在别的地方出错。

③ 才是真正会炸的那个。

四、辨真假
#答案理由
1错权重共享，参数量和长度完全无关
2错整体缩放到 max_norm，方向不变
3错lengths 正是 packing 的输入，必须传
4对训练时 dropout 开着，等于做难题
5错embedding 按索引存，词表变了索引就错位，输出全乱
