二、输入尺寸

用课里的 NiN，把输入尺寸从 96 往下调。最小的能跑通的尺寸是多少？

def out_size(n, k, s=1, p=0):
    return (n + 2 * p - k) // s + 1

def trace(size):
    a = out_size(size, 11, s=4)
    b = out_size(a, 3, s=2)
    c = out_size(b, 5, p=2)
    d = out_size(c, 3, s=2)
    e = out_size(d, 3, p=1)
    f = out_size(e, 3, s=2)
    g = out_size(f, 3, p=1)
    return a, b, c, d, e, f, g

for size in range(90, 140, 2):
    t = trace(size)
    if t[-1] >= 1 and min(t) >= 1:
        print(f"最小可跑 {size}: {t}")
        break

#说法对 / 错 + 理由

21×1 卷积的参数量只和通道数有关，和图片大小无关

参考答案

一、1×1 卷积的参数
配置参数量怎么算
Conv2d(256, 64, 1)16,384256 × 64
Conv2d(64, 256, 1)16,38464 × 256
Conv2d(512, 512, 1)262,144512 × 512
Conv2d(3, 8, 1)243 × 8

「想一想」：一样。都是 16,384——矩阵乘法 A(m×n) @ B(n×k) 里， 翻转 m 和 k 不改变 n × m × k 的量级。

64 × 256 = 256 × 64 = 16,384。

所以降维再升维（Bottleneck）不省参数—— 省的是中间那层的计算量，不是参数量。

三、对照实验

答案是 B 好得多。

方案第一层输出原因
A：11×11 步长 422×22一口气丢掉 3/4 的像素
B：3×3 步长 196×96信息全保留，靠后面的池化慢慢降

这就是课里说的「结构要匹配数据规模」。 在 224×224 上大步长是省算力的必要手段； 在 96×96 上它只剩破坏。

这也是为什么现代网络（ResNet 之后）几乎都用 3×3 + 步长 1 开头， 只在第一层用一次 7×7 步长 2。

四、辨真假
#答案理由
1对核是 1×1，配 padding=0, stride=1 时尺寸完全不变
2对参数量 = 输入通道 × 输出通道 × 1 × 1，不含 H、W
3错零参数，只是对每个通道求平均
4错参数量少只省显存。1×1 卷积要算 H×W 次小矩阵乘，在 GPU 上反而慢
5错它低是因为用错了场景（大核大步长配小图）。 它的两个设计（1×1 卷积、全局平均池化）被后来的网络全盘接受
