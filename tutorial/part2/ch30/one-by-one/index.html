1×1 卷积：一个被名字耽误的东西

这一课在哪

第 27 章讲过卷积的三种超参：核大小、步长、填充。 当时留了一个没细说：核大小为 1 的卷积。

这一课专门讲它。因为它看着没用，实际是后面几章最常用的零件。

先看它长什么样

import torch
import torch.nn as nn

x = torch.randn(1, 3, 4, 4)      # 1 张图，3 通道，4×4

conv = nn.Conv2d(in_channels=3, out_channels=8, kernel_size=1)
out = conv(x)

print(out.shape)      # torch.Size([1, 8, 4, 4])
看什么结果说明
高度宽度 4×4一点没变核是 1×1，不跨位置
通道 3 → 8变了核的个数 = 输出通道
参数量8 × 3 + 8 = 32和图片大小无关

第一反应通常是：只在 1 个像素上扫，能提取什么特征？

问得对。它确实不提取空间特征。

换个角度看，它是什么

把输入 (B, C, H, W) 重新理解一下：

维度平时怎么叫换个叫法
B批量批量
C通道特征维度
H × W空间位置样本
这就是全部的秘密

如果你把每个像素位置看成一个样本， 把 C 个通道看成这个样本的 C 个特征——

那么 1×1 卷积做的事，就是在 H×W 个位置上，各跑一次同一个全连接层。

1×1 卷积 = 逐像素的全连接层。

用代码验证这一点

import torch
import torch.nn as nn

torch.manual_seed(0)
x = torch.randn(2, 3, 5, 5)

conv1x1 = nn.Conv2d(in_channels=3, out_channels=8, kernel_size=1)
linear = nn.Linear(in_features=3, out_features=8)

# conv 权重形状 (8, 3, 1, 1)，删掉最后两个长度 1 的维 → (8, 3)，正好给 Linear
with torch.no_grad():
    linear.weight.copy_(conv1x1.weight.squeeze(-1).squeeze(-1))
    linear.bias.copy_(conv1x1.bias)

# 路径 A：1×1 卷积
out_a = conv1x1(x)

# 路径 B：把每个像素当样本走全连接
flat = x.permute(0, 2, 3, 1).reshape(-1, 3)
out_b = linear(flat).reshape(2, 5, 5, 8).permute(0, 3, 1, 2)

print(torch.allclose(out_a, out_b, atol=1e-6))
True

完全一样。

步操作形状
起点—(2, 3, 5, 5)
①permute(0,2,3,1) 通道挪到末尾(2, 5, 5, 3)
②reshape(-1, 3)(50, 3)
③linear(50, 8)
④拼回四维(2, 8, 5, 5)

50 = 2 × 5 × 5——两张图，每张 25 个像素，一共 50 个样本。

那为什么不用 Linear 写

因为 Linear 写法要把四维拆成二维再拼回去，permute/reshape 的顺序错一个都不会报错，只是结果全错。

而 1×1 卷积输入输出都是四维，空间结构一直保持，写错会报形状错。

同一件事，写成 1×1 卷积更不容易出错。

它到底能干什么

三个用途，按重要性排：

#用途具体
①降通道256 → 64，参数和后续计算量都砍掉 3/4
②升通道64 → 256，便宜地加容量
③加非线性1×1 卷积 + ReLU 相当于在通道之间插一层小全连接

① 降通道为什么省

假设你要接一个 3×3 卷积，输入 256 通道，输出 256 通道：

import torch.nn as nn

def count(module):
    return sum(p.numel() for p in module.parameters())

# 直接算
direct = nn.Conv2d(256, 256, kernel_size=3, padding=1)
print(count(direct))                          # 590,080

# 先降到 64，算完再升回去
bottleneck = nn.Sequential(
    nn.Conv2d(256, 64, kernel_size=1),        # 降通道
    nn.Conv2d(64, 64, kernel_size=3, padding=1),
    nn.Conv2d(64, 256, kernel_size=1),        # 升通道
)
print(count(bottleneck))                      # 69,632
做法参数
直接 256→256 的 3×3590,080
1×1 降 → 3×3 → 1×1 升69,632

省了 88%。这个「先压窄再算再放开」的结构叫Bottleneck（瓶颈），第 31 章 ResNet 里会正式见到它。

但省的不总是参数

如果压缩前后通道一样（比如 64 → 64）， 那 1×1 反而是加参数。

上表能省 88%，是因为中间真的变窄了（256 → 64 → 256）。

Bottleneck 的关键是「中间窄」，不是「有几个 1×1」。

为什么它算得慢

3×3 卷积一个参数用一次，1×1 也是。 但 1×1 要被调用 H×W 次。

# 224×224 的图上，一个 1×1 卷积要算多少次
H = W = 224
print(H * W)      # 50,176 次小矩阵乘

GPU 最怕这种「很多很小」的运算——每次都要启动一个新核，调度开销比计算本身还大。

所以 1×1 卷积参数少、显存省，但速度不快。 这和上一章 AlexNet 那个观察是同一件事。
