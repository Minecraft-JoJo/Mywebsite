手算一次 LSTM

这一课在哪

前两课讲清了结构（C 是高速公路、三个门各管什么）。这一课一步不落地算一遍。

目的很单纯：算完之后，公式里每个符号你都能对上一个具体的数。

设定：把维度压到 2

量值说明
输入维度1xt​=[1.0]
隐藏维度2C 和 h 各 2 个数
batch1只算一个样本

这一步的输入和上一步的状态：

x  = [1.0]
h' = [0.5, 0.2]      上一步的隐状态
C' = [0.8, -0.3]     上一步的记忆元

为了让手算能做，三个门和候选的结果我直接给（真实情况是它们也由权重算出来）：

f  = [0.9, 0.1]       遗忘门
i  = [0.5, 0.8]       输入门
g  = [0.6, -0.4]      候选 C~
o  = [0.7, 0.9]       输出门

第 1 步：遗忘门作用在旧记忆上

f⊙C′=[0.90.1​]⊙[0.8−0.3​]=[0.72−0.03​]

看这两个数：第一个位置乘 0.9，几乎全留（0.8 → 0.72）； 第二个位置乘 0.1，几乎丢光（-0.3 → -0.03）。

为什么要看这一行

如果门是一个数，那这两个位置只能一起留或一起丢。

但门是向量——同一时刻，不同位置可以有不同的策略。

这就是为什么 LSTM 能记住「某几个特征」同时忘掉「另外几个」。

第 2 步：输入门作用在候选上

i⊙g=[0.50.8​]⊙[0.6−0.4​]=[0.30−0.32​]

候选说「要写 0.6 和 -0.4」，输入门说「第一个写一半，第二个写八成」。

第 3 步：两路相加，得到新的 C

Ct​=[0.72−0.03​]+[0.30−0.32​]=[1.02−0.35​]

C 从 [0.8,−0.3] 变成 [1.02,−0.35]。

位置旧值留下写入新值
第 1 个0.8+0.72+0.301.02
第 2 个-0.3-0.03-0.32-0.35

第一个位置明显变大（0.8 → 1.02），旧的一大半留下 + 新的一小块加进来。

第二个位置几乎没变（-0.3 → -0.35）—— 旧的被丢掉 90%，但新写进来的也是负的，刚好抵消。

第 4 步：从 C 里读出 h

先过 tanh：

tanh(Ct​)=[tanh(1.02)tanh(−0.35)​]=[0.770−0.336​]

再乘输出门：

ht​=o⊙tanh(Ct​)=[0.70.9​]⊙[0.770−0.336​]=[0.539−0.303​]
量值
旧 C[0.8, -0.3]
新 C[1.02, -0.35]
旧 h[0.5, 0.2]
新 h[0.539, -0.303]
注意 h 和 C 不是一回事

C 是 [1.02, -0.35]，h 是 [0.539, -0.303]。

C 可以超过 1，h 永远在 (-1, 1) 之间—— 因为 h 过了 tanh。

C 是「完整的记忆」，h 是「这一步对外说的那部分」。

用代码核对

import torch

C_prev = torch.tensor([0.8, -0.3])
h_prev = torch.tensor([0.5, 0.2])

f = torch.tensor([0.9, 0.1])
i = torch.tensor([0.5, 0.8])
g = torch.tensor([0.6, -0.4])
o = torch.tensor([0.7, 0.9])

C = f * C_prev + i * g
h = o * torch.tanh(C)

print(C)      # tensor([ 1.0200, -0.3500])
print(h)      # tensor([ 0.5390, -0.3020])

最关键的一次：f = 1，i = 0

C_prev = torch.tensor([0.8, -0.3])
f = torch.tensor([1.0, 1.0])       # 全留
i = torch.tensor([0.0, 0.0])       # 不写
g = torch.tensor([0.6, -0.4])

C = f * C_prev + i * g
print(C)      # tensor([ 0.8000, -0.3000])     一个数都没变
这两行就是 LSTM 存在的全部理由

f=1、i=0 时，C 原样传下去，一个数都不变。

意味着：50 步之前的信息，可以一路原封不动传到今天。

RNN 做不到——它的 h 每步都被 tanh 重新算， 没有任何办法「保持不变」。

再看 f = 0

f = torch.tensor([0.0, 0.0])       # 全忘
C = f * C_prev + i * g
print(C)      # tensor([0., 0.])           记忆被清空

C 直接被清零。这就是「遗忘」的字面含义。

用 nn.LSTMCell 核对整步

LSTMCell 是只看一步的版本，正好用来核对：

import torch
import torch.nn as nn

torch.manual_seed(0)

# 输入 1 维，隐藏 2 维
cell = nn.LSTMCell(input_size=1, hidden_size=2)

# 手工把三个门和候选设成上面给的值
# 权重排列顺序是 i, f, g, o
with torch.no_grad():
    cell.weight_ih.zero_()
    cell.weight_hh.zero_()
    cell.bias_ih.copy_(torch.tensor([0.5, 0.8,   0.9, 0.1,   0.6, -0.4,   0.7, 0.9]))
    cell.bias_hh.zero_()

# 但门的输出是 sigmoid/tanh(偏置)，不是偏置本身
# 所以要反解：sigmoid(x) = 目标值
def inv_sigmoid(y):
    return torch.log(y / (1 - y))

def inv_tanh(y):
    return 0.5 * torch.log((1 + y) / (1 - y))

with torch.no_grad():
    raw = torch.tensor([
        *inv_sigmoid(torch.tensor([0.5, 0.8])).tolist(),   # i
        *inv_sigmoid(torch.tensor([0.9, 0.1])).tolist(),   # f
        *inv_tanh(torch.tensor([0.6, -0.4])).tolist(),     # g
        *inv_sigmoid(torch.tensor([0.7, 0.9])).tolist(),   # o
    ])
    cell.bias_ih.copy_(raw)

x = torch.tensor([[1.0]])
h0 = torch.tensor([[0.5, 0.2]])
c0 = torch.tensor([[0.8, -0.3]])

h1, c1 = cell(x, (h0, c0))
print(c1)     # tensor([[ 1.0200, -0.3500]])
print(h1)     # tensor([[ 0.5390, -0.3020]])
核对时要注意的事

门的原始输出是 σ(偏置)，不是偏置本身。

所以要先用 inv_sigmoid 反解出偏置该填多少—— 否则填进去的 0.9 会被再 sigmoid 一次变成 0.71。

这个坑在手算和代码核对之间很常见。
