GRU：把三个门压成两个

这一课在哪

LSTM 有三个门、两个状态（h 和 C），参数是 RNN 的 4 倍。

GRU 是它的精简版：两个门、一个状态。

LSTMGRU
门遗忘 / 输入 / 输出 + 候选重置 / 更新
状态h 和 C只有 h
参数（128→64）49,66437,248

去掉的是哪两样

GRU 砍掉了两样东西，都有道理：

砍掉理由
单独的 Ch 兼任记忆。h_t 直接当记忆传递
输出门没有 C 就没有「从 C 里读多少」这回事
输入门 + 遗忘门合并成一个更新门——两者加起来正好是 1
最后一条是关键洞察

LSTM 里，遗忘和写入是两件独立的事， 两个门各算各的。

但「忘记多少」和「写多少」其实是一件事的两面—— 忘了 30% 就等于腾出 30% 的位置。

GRU 用一个门 z 同时表示：留 z，写 1−z。

结构长什么样

两个门：

门回答什么
重置门 rt​算候选时，旧的记忆参考多少
更新门 zt​新状态里，旧的留多少（剩下的给新的）

三个公式

rt​zt​h~t​ht​​=σ(Wxr⊤​xt​+Whr⊤​ht−1​+br​)=σ(Wxz⊤​xt​+Whz⊤​ht−1​+bz​)=tanh(Wxh⊤​xt​+Whh⊤​(rt​⊙ht−1​)+bh​)=zt​⊙ht−1​+(1−zt​)⊙h~t​​

看第二行和第四行，是一对：

门的值新状态 h 里
zt​=1全是旧的，新信息被忽略
zt​=0全新内容，旧记忆不参与
zt​=0.5各一半

这叫凸组合：两个系数加起来恒等于 1，结果是两者的加权平均。

z 接近 1 意味着「跳过一个时间步」

zt​→1 时 ht​≈ht−1​， 这一步的输入 xt​ 基本被忽略。

相当于在依赖链条上跳过了第 t 步。

这正是解决长距离依赖的机制——不需要处理的信息就整步跳过， 梯度也就原样传过去了。

重置门在干什么

它在算候选之前起作用：rt​⊙ht−1​。

rt​意思什么时候有用
接近 1旧记忆全参与新内容和前文有关
接近 0旧记忆不参与新内容是一个全新的开头，

举个例子：读到一个新的句号，后面是另一句话了。 重置门可以关掉，把上一句的记忆挡在候选之外。

和 LSTM 的对照

LSTM 里这个作用是遗忘门干的（作用在 C 上）。

GRU 里分成两个：重置门作用在候选的计算上，更新门作用在最后的混合上。

一个管「算的时候参考多少」，一个管「最后留多少」。

GRU 比 LSTM 少 25%，比 RNN 多 3 倍。

gru = nn.GRU(128, 64, batch_first=True)
print(gru.weight_ih_l0.shape)      # torch.Size([192, 128])
print(gru.weight_hh_l0.shape)      # torch.Size([192, 64])

192 = 3 × 64——三个门叠在一起，和 LSTM 的 256 = 4 × 64 一个道理。

用起来什么差别

import torch

x = torch.randn(4, 10, 128)

rnn  = nn.RNN(128, 64, batch_first=True)
gru  = nn.GRU(128, 64, batch_first=True)
lstm = nn.LSTM(128, 64, batch_first=True)

print(rnn(x)[1].shape)      # torch.Size([1, 4, 64])
print(gru(x)[1].shape)      # torch.Size([1, 4, 64])
print(lstm(x)[1][0].shape)  # torch.Size([1, 4, 64])   ← 多一层
层返回值怎么取最后一步
nn.RNN(out, h_n)h_n[0]
nn.GRU(out, h_n)h_n[0]
nn.LSTM(out, (h_n, c_n))h_n[0]，但要先拆元组
这个坑我踩过

写 _, h = self.rnn(packed) 时：

RNN/GRU 的 h 是 (1, B, H)，h[0] 就对了。

LSTM 的 h 是元组 (h_n, c_n)，h[0] 拿到的是 h_n（还是三维），还要再 [0] 一次。

不拆的话报错是Expected input batch_size (1) to match target batch_size (64)。

正确写法

_, h = self.rnn(packed)

if self.kind == "lstm":
    h_n, _c_n = h
    last = h_n[0]
else:
    last = h[0]

怎么选

情况建议
不知道选哪个先试 GRU，参数少、通常不差
很长的序列（几百步以上）LSTM 的 C 通道更干净
显存紧GRU
要极致效果两个都跑，看验证集
