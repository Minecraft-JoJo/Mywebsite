只改一行的代码

import torch.nn as nn

class SentimentNet(nn.Module):
    def __init__(self, kind, vocab_size, embed_dim=128, hidden=64,
                 num_classes=2, dropout=0.3):
        super().__init__()
        self.kind = kind

        self.embedding = nn.Embedding(vocab_size, embed_dim, padding_idx=0)

        RNN = {"rnn": nn.RNN, "lstm": nn.LSTM, "gru": nn.GRU}[kind]
        self.rnn = RNN(embed_dim, hidden, batch_first=True)

        self.dropout = nn.Dropout(dropout)
        self.fc = nn.Linear(hidden, num_classes)

    def forward(self, x, lengths):
        embedded = self.embedding(x)
        packed = pack_padded_sequence(
            embedded, lengths.cpu(), batch_first=True, enforce_sorted=False,
        )
        _, h = self.rnn(packed)

        if self.kind == "lstm":
            h_n, _c_n = h          # LSTM 返回元组
            last = h_n[0]
        else:
            last = h[0]            # RNN / GRU 直接是张量

        return self.fc(self.dropout(last))

整个改动就是这两处：换层、拆元组。

三个值得注意的地方

① 第一轮就差 13 个点

模型ep1 dev
RNN64.50%
LSTM77.83%
GRU73.00%

这是门控机制最直接的证据。

第一轮训练时模型还很笨，但 LSTM/GRU 已经能把长距离的信息传下去了—— RNN 做不到，它只能看到最后十几个字。

这个差距不是「学得更快」

门控改的不是学习速度，是信息能传多远。

RNN 的结构决定了它不知道第 1 个字； LSTM 的结构允许它知道。

所以第一轮就差这么多——不是训练效率问题，是能力上限问题。

② GRU 反超了 LSTM

90.83% vs 87.83%——GRU 高 3 个点， 而且参数少 12,416 个，每轮还快 0.3 秒。

这有点反常识。通常的说法是「LSTM 更强，GRU 更快」。

为什么这里反过来了？三个可能：

#原因
①数据量小（9600 条），参数少的模型更好训
②句子不长（评论平均 50~100 字），LSTM 的 C 通道优势用不上
③GRU 的门更少，梯度传播路径更短
这个结果不普适

换一个任务、换一个数据集，结论可能完全相反。

在很长的序列（几百步以上）、大数据集上， LSTM 的 C 通道通常表现更好。

所以「哪个更好」这个问题没有通用答案——要跑。

③ 第 7 轮 LSTM 掉了一下

轮LSTM dev
687.50%
786.00% ↓
887.67% ↑

但 train 一直在涨（92.57% → 93.54%）—— 这是过拟合的早期信号，验证集开始不跟着涨了。

正确做法是早停在第 6 轮，或者加正则。

为什么还是上不了 95%

GRU 到 90.83% 已经不错了。剩下 9 个点卡在哪？

#瓶颈怎么突破
①只用最后一步 h_n用注意力对所有步加权
②只能单向读双向 RNN（bidirectional=True）
③按字切，否定词难学用 BERT 这类预训练模型

第 ① 条是第 35 章之后要讲的注意力机制—— 它就诞生于「只用最后一步不够」这个问题。

这一章真正要记住的

RNN → LSTM → GRU 的本质改动不是「加了几个门」， 而是给梯度修了一条不必穿过连乘的路。

第 34.1 课算过：RNN 20 步后梯度剩 1e-6。 LSTM 把衰减交给 ft​， GRU 把衰减交给 zt​。

都是「让模型自己决定该记多久」。
