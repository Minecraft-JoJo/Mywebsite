三个门和一个候选

这一课在哪

上一课认识了三个门和一个候选的大致分工，还走了一遍完整计算。

这一课把它们一个一个拆开：每个门具体算什么、 为什么用这个激活函数、形状是什么、坏了会怎样。

门上一课的一句话
遗忘门 ft​旧的 C 留多少
输入门 it​新内容写多少
候选 C~t​要写的新内容本身
输出门 ot​h 露出多少 C

先说一个共同点

三个门的公式长得一模一样：

ft​it​ot​​=σ(Wxf⊤​xt​+Whf⊤​ht−1​+bf​)=σ(Wxi⊤​xt​+Whi⊤​ht−1​+bi​)=σ(Wxo⊤​xt​+Who⊤​ht−1​+bo​)​

同样的输入，同样的结构，只是权重不同。

所以实现上可以合并成一次矩阵乘法—— 这也是 PyTorch 内部的做法。

import torch
import torch.nn as nn

lstm = nn.LSTM(input_size=128, hidden_size=64, batch_first=True)

print(lstm.weight_ih_l0.shape)      # (256, 128)
print(lstm.weight_hh_l0.shape)      # (256, 64)
print(lstm.bias_ih_l0.shape)        # (256,)
权重形状256 是怎么来的
weight_ih_l0(256, 128)4 × 64——三个门 + 候选叠在一起
weight_hh_l0(256, 64)同上
bias_ih_l0(256,)同上
4 × 64 = 256 这个数很关键

LSTM 的参数是 RNN 的正好 4 倍，原因就在这：三组门 + 一组候选，被拼成一个大矩阵一起算。

nn.RNN(128, 64) 是 (64, 128)；nn.LSTM(128, 64) 是 (256, 128)。

顺序是输入门、遗忘门、候选、输出门（i, f, g, o）， 各占 64 行。

遗忘门：ft​

ft​=σ(Wxf⊤​xt​+Whf⊤​ht−1​+bf​)

它只回答一个问题：旧的记忆，每个位置留多少？

import torch

# 假设算出来的遗忘门是这两个值
f = torch.tensor([0.95, 0.05])

# 旧记忆
C_prev = torch.tensor([1.0, 1.0])

print(f * C_prev)      # tensor([0.9500, 0.0500])

第一个位置留了 95%，第二个位置只留了 5%。同一个时刻，不同位置可以有不同的遗忘策略。

f 接近 1 的时候发生了什么

ft​=1 意味着 Ct​=Ct−1​+⋯—— 旧记忆原封不动地传下来。

这就是上一课说的「高速公路」。

而 RNN 没有任何办法做到这件事——它的 h 每步都被 tanh 重算。

为什么遗忘门初始值该偏大

有些实现会把遗忘门的偏置初始化为 1。为什么？

偏置初值训练初期 f 大约后果
0σ(0)=0.5一开始就丢掉一半记忆
1σ(1)=0.73先记住，学出来再忘
import torch

print(torch.sigmoid(torch.tensor([0.0, 1.0, 2.0])))
# tensor([0.5000, 0.7311, 0.8808])

先倾向于记住，让梯度能传远； 等训练起来，模型自己会把该忘的忘掉。

输入门：it​

it​=σ(Wxi⊤​xt​+Whi⊤​ht−1​+bi​)

它回答：这一步的新东西，每个位置写多少？

注意它不管「写什么」——那是候选的事。它只管写多少。

i = torch.tensor([0.9, 0.1])
C_tilde = torch.tensor([0.5, 0.5])

print(i * C_tilde)      # tensor([0.4500, 0.0500])

候选给了两个位置都是 0.5，但输入门让第一个位置进了 0.45，第二个只进 0.05。

候选：C~t​

先说清楚：候选不是门

LSTM 有 三个门：遗忘门、输入门、输出门。候选不是门。

区别在输出范围：门的输出是 0~1（sigmoid）， 表示「过多少」；候选的输出是 -1~1（tanh）， 是「内容本身」。

代码里 weight_ih_l0 是 (256, 128) = 4 × 64， 这 4 组是「三组门 + 一组候选」，被拼在一起算，不代表有四个门。

C~t​=tanh(Wxc⊤​xt​+Whc⊤​ht−1​+bc​)

唯一用 tanh 的那个。为什么？

门激活范围为什么
遗忘/输入/输出σ(0, 1)当比例用，不能是负数
候选tanh(−1, 1)是内容，要能加也要能减
这一条很重要

门的输出是比例，乘上去只能「按比例缩」，不能翻转符号。

候选是内容，需要能表达「往负方向推」。

如果候选用 sigmoid，那 C 只增不减，记忆就废了一半。

输出门：ot​

ot​=σ(Wxo⊤​xt​+Who⊤​ht−1​+bo​)
ht​=ot​⊙tanh(Ct​)

它回答：这一步要对外露出多少记忆？

注意 ot​ 不改变 C。C 已经更新完了，输出门只是决定读出多少。

C = torch.tensor([1.02, -0.35])
o = torch.tensor([0.7, 0.9])

h = o * torch.tanh(C)
print(h)              # tensor([ 0.5390, -0.3020])
print(C)              # tensor([ 1.0200, -0.3500])   C 没变
输出门接近 0 会怎样

ot​=0 时 ht​=0——这一步对外什么都不说，但 C 照样更新。

这在处理长句时有用：中间那些没用的词， 信息照存进 C，但不必污染输出。

所有张量的形状

设 batch=32, 输入=128, hidden=64：

张量形状说明
xt​(32, 128)这一步的输入
ht−1​(32, 64)上一步的隐状态
ft​,it​,ot​(32, 64)三个门，各一个
C~t​(32, 64)候选
Ct​(32, 64)记忆元
ht​(32, 64)隐状态

全都是同一个形状。这就是为什么 ⊙能直接作用——逐元素乘，形状不变。

参数量

def count_lstm(input_size, hidden_size):
    # 三组门 + 候选，各一组 W_x, W_h, b
    per_gate = input_size * hidden_size + hidden_size * hidden_size + hidden_size
    return 4 * per_gate

print(count_lstm(128, 64))      # 49,664

import torch.nn as nn
lstm = nn.LSTM(128, 64, batch_first=True)
print(sum(p.numel() for p in lstm.parameters()))     # 49,664
项计算参数
一个门的 Wx​128 × 648,192
一个门的 Wh​64 × 644,096
一个门的 b6464
一个门合计12,352
四组（3 门 + 候选）4 × 12,35249,408

49,408 和 49,664 差 256——那是nn.LSTM 把 bias 拆成了 bias_ih 和 bias_hh 两份。

门坏了会怎样

如果后果
遗忘门恒为 0C 每步被清空，变成普通的 RNN
遗忘门恒为 1C 只增不减，很快数值爆炸
输入门恒为 0C 永远不变，学不到新东西
输出门恒为 0h 恒为 0，梯度传不回去
所以门必须「学」

三个门如果都是固定的，LSTM 就退化成 RNN 或者干脆不能用。

它的全部价值在于：门是学出来的，每个位置、每个时刻都可以不同。
