手算一次解码的注意力

这一课在哪

上一课讲清了结构和公式。这一课一步步算出来。

算完之后你会看到一件关键的事：权重把大部分给了某一个源词， 这就是「对齐」出现了。

设定：压到 2 维

量值角色
编码器三个输出h1​=[1,0]、h2​=[0,1]、h3​=[1,1]K 和 V
解码器当前状态s0​=[1,0]Q
维度都是 2多了手算不动

把权重矩阵取成单位矩阵

加性注意力的公式是：

et​=wv⊤​tanh(Wq​s0​+Wk​ht​)

为了能手算，取 Wq​=Wk​=I（单位矩阵），wv​=[1,1]。

于是公式退化成：

et​=[1,1]⊤tanh(s0​+ht​)=tanh(s0​+ht​)1​+tanh(s0​+ht​)2​
这样简化会失真吗

不会。计算流程完全一样，只是省掉了「各乘一个矩阵」那一步。

真实模型里 Wq​、Wk​、wv​都是训练出来的——它们决定了「什么样的 q 和 k 才算配」。

这里取单位矩阵，意思是「原样相加再压缩」，够看出三步的流程。

第 1 步：打分

Q 和每个 K 各算一次。三个源词，算三次。

对 h1​

s0 + h1 = [1,0] + [1,0] = [2, 0]
tanh:  tanh(2) = 0.9640   tanh(0) = 0.0000
求和:  0.9640 + 0.0000 = 0.9640

e1 = 0.9640

对 h2​

s0 + h2 = [1,0] + [0,1] = [1, 1]
tanh:  tanh(1) = 0.7616   tanh(1) = 0.7616
求和:  0.7616 + 0.7616 = 1.5232

e2 = 1.5232

对 h3​

s0 + h3 = [1,0] + [1,1] = [2, 1]
tanh:  tanh(2) = 0.9640   tanh(1) = 0.7616
求和:  0.9640 + 0.7616 = 1.7256

e3 = 1.7256
源词s0​+ht​et​
h₁[2, 0]0.9640
h₂[1, 1]1.5232
h₃[2, 1]1.7256
看一眼这三个分数

h3​=[1,1] 分数最高。h1​=[1,0] 最低。

为什么？因为 s0​=[1,0] 和 h3​ 相加后两个维度都有值（[2,1] 的 tanh 是 0.96 和 0.76）， 而和 h1​ 相加后第二个维度是 0，只贡献了一半。

「两个维度都被激活」的那个分数更高。

第 2 步：softmax

三个分数直接进 softmax 会太集中，先看原始值——这里数值不大，可以直接做。

取指数：
  e^0.9640 = 2.6222
  e^1.5232 = 4.5868
  e^1.7256 = 5.6160

  合计 = 2.6222 + 4.5868 + 5.6160 = 12.8251

归一化：
  α1 = 2.6222 / 12.8251 = 0.2045
  α2 = 4.5868 / 12.8251 = 0.3576
  α3 = 5.6160 / 12.8251 = 0.4379

  相加 = 1.0000
源词et​exp(et​)αt​
h₁0.96402.62220.2045
h₂1.52324.58680.3576
h₃1.72565.61600.4379
合计12.82511.0000
softmax 把差距放大了

分数上 h₃ 只比 h₁ 高 79%（1.7256 vs 0.9640）。

权重上 h₃ 是 h₁ 的 2.14 倍（0.4379 vs 0.2045）。

这是 softmax 的特性：它会把相对差距放大。 分数差一点，权重差很多。

第 3 步：加权求和

用三个权重去平均三个 ht​（也就是 V）：

第 1 维：
  0.2045 × 1  = 0.2045      (h1 的第1维)
  0.3576 × 0  = 0           (h2 的第1维)
  0.4379 × 1  = 0.4379      (h3 的第1维)
  合计          0.6424

第 2 维：
  0.2045 × 0  = 0
  0.3576 × 1  = 0.3576
  0.4379 × 1  = 0.4379
  合计          0.7955
c1​=[0.64240.7955​]

这个 c1​ 就是解码器生成第 1 个词时， 从源句里提取出来的信息。

用代码核对

import torch

h = torch.tensor([[1., 0.], [0., 1.], [1., 1.]])    # K 和 V
s0 = torch.tensor([1., 0.])                          # Q

# W_q = W_k = I, w_v = [1, 1]
pre = s0.unsqueeze(0) + h                             # (3, 2)
e = torch.tanh(pre).sum(dim=1)                        # (3,)
print(e)          # tensor([0.9640, 1.5232, 1.7256])

alpha = torch.softmax(e, dim=-1)
print(alpha)      # tensor([0.2045, 0.3576, 0.4379])

c = alpha @ h
print(c)          # tensor([0.6424, 0.7955])

「对齐」在哪

把权重排一下：

源词权重条形
h₁0.2045████
h₂0.3576███████
h₃0.4379████████
这就是注意力在 seq2seq 里的核心价值

三个源词，模型给它们分了不同的关注度。

而且这个分配是每一步重算的——生成第 2 个词时，s 变了，权重就会换一套。

普通的 seq2seq 做不到这件事： 它只有一团固定的 h，三个词的信息搅在一起，分不开。

这个例子里的权重有点「平」

0.20 / 0.36 / 0.44——差距不算悬殊。原因有两个：

#原因
①把 Wq​、Wk​ 取成了单位矩阵， 没有「学出该关心什么」的能力
②三个 ht​ 都只有 2 维，而且都很像 （[1,0] / [0,1] / [1,1]）

训练好的真实模型里，权重常常是0.9 / 0.05 / 0.05 这种， 几乎一对一——那才是清晰的「对齐」。

换成点积会怎样

同样的三个 K 和这个 Q，如果改用点积打分：

scores = s0 @ h.T                  # 点积，不除以 sqrt(d)
print(scores)     # tensor([1., 0., 1.])

alpha = torch.softmax(scores, dim=-1)
print(alpha)      # tensor([0.4223, 0.1554, 0.4223])
打分方式权重
加性（本课）0.2045 / 0.3576 / 0.4379
点积0.4223 / 0.1554 / 0.4223
两者给出的结论不同

点积认为 h1​ 和 h3​ 一样重要（都是 0.42）。

加性认为 h3​ 最重要、h1​ 最不重要。

因为点积只看方向重合：s₀=[1,0] 和 h₁=[1,0] 完全同向（点积 1）， 和 h₃=[1,1] 点积也是 1，分不出高下。

加性会把两个维度加起来一起看，所以能区分。

数值含义

三个权重0.2045 / 0.3576 / 0.4379和为 1
