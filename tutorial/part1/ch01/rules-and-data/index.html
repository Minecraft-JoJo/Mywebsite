规则与数据

写规则的路走不通

写程序通常是这样一个方向：人把规则想好，交给程序，程序处理数据给出答案。

判断一封邮件是不是垃圾邮件，你写：

if "中奖" in text or "免费领取" in text:
    return "垃圾邮件"

跑起来没问题。但对方把"中奖"改成"中 奖"、"中*奖"、"恭喜中奖"，你就得再加三条规则。再往后是几百条、几千条。规则永远补不完，因为对手在变，而你的规则是死的。

有些事根本写不出规则

还有一类任务，规则连写都写不出来。下面是几件计算机每天都在做的事：

任务你怎么用 if 写规则？
判断一张照片里是不是猫"有两只耳朵"？折耳猫呢？背影呢？夜里拍的糊的呢？
把一段语音变成文字同一个人说同一句话，每次波形都不一样
把中文翻成英文语序、语气、成语，没有固定模板
认出信封上的手写邮编每个人写的 3 都不一样

这些任务的共同点：人能给出答案，但说不出规则。你一眼就知道那是只猫，但你无法把这个判断过程写成 if。

换一个方向

机器学习换了个方向：

你给机器十万封已经标注好的邮件——这封是垃圾、这封不是——它自己找出一套判断规则。你不告诉它规则，你只给它例子。

这件事说起来只有一句：从数据里找出一个函数。

它叫什么名字不重要，重要的是它是个函数——给输入，出输出。
