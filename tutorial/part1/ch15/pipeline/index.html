Pipeline

先看一个反例

这几行代码看起来完全正常：

scaler = StandardScaler()
X_scaled = scaler.fit_transform(X)      # 用了全部数据

X_train, X_test = train_test_split(X_scaled)

model.fit(X_train, y_train)

但它有数据泄漏。

漏在哪

fit_transform(X) 用了全部数据的均值和标准差，包括测试集。

这意味着测试集的分布信息提前进入了训练过程。你测出来的分数会虚高。

这个错误非常常见，而且不会报错——它只是让你的评估结果不可信。

正确写法

X_train, X_test, y_train, y_test = train_test_split(X, y)
scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)   # 只 fit 训练集
X_test  = scaler.transform(X_test)        # 测试集只 transform

能对，但容易漏。步骤一多（标准化 + 编码 + 填充 + PCA），漏一个就白干。

Pipeline 的解法

把所有步骤串成一个对象，让它只在训练集上 fit：

pipe = Pipeline([
    ("impute", SimpleImputer()),
    ("scale",  StandardScaler()),
    ("pca",    PCA(n_components=10)),
    ("model",  RandomForestClassifier()),
])

pipe.fit(X_train, y_train)
pipe.score(X_test, y_test)

关键点：

  • pipe.fit 会把每一步只在训练数据上 fit
  • 预测时自动按顺序 transform 新数据
  • 交叉验证时，每一折的预处理各自独立 fit——泄漏从根源上不可能发生
第三条是最重要的

你写 cross_val_score(pipe, X, y) 时，sklearn 会在每一折内部重新 fit 整个 Pipeline。

手动分步写的话，你得自己保证每一折都不泄漏——几乎一定会出错。

还有一个好处：模型只有一个对象

保存模型时，joblib.dump(pipe) 存的是预处理 + 模型的完整链条。

部署时直接 pipe.predict(新数据)，不用记得“要先标准化再编码再预测”。

手动分步的话，忘了某一步预处理是最常见的线上事故之一。

ColumnTransformer：不同列走不同流程

真实数据里，数值列和类别列要分别处理：

pre = ColumnTransformer([
    ("num", StandardScaler(), ["年龄", "收入"]),
    ("cat", OneHotEncoder(),  ["城市", "职业"]),
])

pipe = Pipeline([("pre", pre), ("model", LogisticRegression())])
这样写的好处

每个特征走哪条流程，写成声明式的配置。加一个特征只需改一行。

而且 Pipeline 会自动记住每列用了什么变换——预测时不会错位。

这一课解决了什么

Pipeline 不是“代码整洁”，它是防数据泄漏的机制。
