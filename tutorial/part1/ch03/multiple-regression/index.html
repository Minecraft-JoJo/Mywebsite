多元线性回归

一个特征不够用

第 2 章只有面积一个特征。现实里房价显然不只由面积决定：

房源面积楼层房龄卧室数离地铁
A100 ㎡123 年3400 m
B100 ㎡120 年21200 m

两套面积一样，价格很可能差几十万。只盯面积，模型永远解释不了这个差别。

所以把特征从 1 个扩到 n 个。记第 i 个样本的 n 个特征为：

x(i)=(x1(i)​, x2(i)​, …, xn(i)​)

上标 (i) 是"第几个样本"，下标 j 是"第几个特征"。这两个索引别搞混。

把模型展开

每个特征配一个权重：

f(x)=w1​x1​+w2​x2​+w3​x3​+w4​x4​+b

拿 A 房举例，假设 w=(2.8, 0.5, −1.2, 8, −0.02)、b=40：

f=2.8×100+0.5×12+(−1.2)×3+8×3+(−0.02)×400+40
=280+6−3.6+24−8+40=338.4 万元

每一项的含义：

项值读法
2.8×100280面积每多 1 ㎡，价格加 2.8 万
0.5×126楼层每高 1 层，加 0.5 万
−1.2×3−3.6房龄每多 1 年，减 1.2 万
8×324每多一个卧室，加 8 万
−0.02×400−8离地铁每远 1 m，减 0.02 万
权重的正负号本身就是知识

权重是正的，这个特征推高价格；负的，拉低价格。

w2​=0.5 为正，说明在这批数据里楼层越高越贵；w3​=−1.2 为负，房龄越大越便宜。

这些数是模型从数据里学到的，不是你写的。但前提是数据里真有这个规律——喂它一堆烂数据，它也会一本正经地学出离谱的权重。

写成向量

四个特征就要写四项，二十个特征呢？

把特征和权重各自打包成向量：

x=​x1​x2​⋮xn​​​,w=​w1​w2​⋮wn​​​

模型就变成两个向量的点积加一个常数：

f(x)=w⊤x+b=j=1∑n​wj​xj​+b

w⊤ 是转置，写成行向量好和列向量 x 相乘。初学时把它当成"两个向量逐项相乘再求和"的记号即可。

同一个东西的不同写法

w⊤x、w⋅x、⟨w,x⟩、x⊤w —— 全都是同一个东西：逐项相乘再求和，结果是一个数。

看到不同写法别慌，认准"逐项乘、加起来"就行。

这就是多元线性回归

多元线性回归（multiple linear regression）：输入是多个特征组成的向量，输出仍是 w⊤x+b。

"线性"指的是对参数线性，不是"图像是一条直线"。哪怕你把面积平方变成新特征 x2​=x12​，只要还是 w2​x2​ 的形式，模型依然是线性的。

特征从 1 个变成 2 个，模型就不再是一条直线——它是一张平面。蓝点是样本，绿色平面是拟合出来的模型。三个特征以上就画不出来了，但道理一样，只是又升了一维。

损失函数和梯度的形式一点没变，只是每个参数多了一个下标：

J(w,b)=2m1​i=1∑m​(w⊤x(i)+b−y(i))2
∂wj​∂J​=m1​i=1∑m​(y^​(i)−y(i))xj(i)​,∂b∂J​=m1​i=1∑m​(y^​(i)−y(i))

好消息是：代码几乎不用改，因为 numpy 会把循环干掉。

向量化到底省了什么

要算 w1​x1​+⋯+wn​xn​。

不用向量化，只能写循环：

s = 0.0
for j in range(n):
    s += w[j] * x[j]

用向量化，一行：

s = w @ x

区别不只是少敲几个字。实测（这台机器上，n=106）：

写法耗时相对速度
Python for 循环0.706 s1×
numpy 点积0.0083 s85×

差了八十五倍，而且 n 越大差距越大。

为什么快这么多

Python 的 for 循环每转一圈都要做类型检查、对象查找、方法调用——这些工作在 C 里都是零成本的。

numpy 数组在内存里是一整块连续的数字，点积直接把整块交给底层 BLAS 库。BLAS 是几十年来为矩阵运算优化的 C/Fortran 代码，会用上 SIMD 指令和多核并行。

到了深度学习这件事更极端：GPU 一次能算几千个乘加，Python 循环只能一个一个来。所以"能不能写成矩阵运算"直接决定你的代码跑几秒还是几小时。

别急着迷信速度

85 倍是 n=106 时测的。如果 n=5，写循环可能反而更快——numpy 每次调用都有固定开销。

向量化的收益随数据规模增长。 小数据写清楚比写快重要。

numpy 上手

下面这些够用很久。

创建与形状

import numpy as np

x = np.array([45, 52, 58])            # 一维，3 个元素
X = np.array([[45, 3], [52, 7]])      # 二维：2 行 2 列

x.shape    # (3,)
X.shape    # (2, 2)
X.ndim     # 2
出错先看 shape

绝大多数 bug 不是数学错了，是形状不对：本该 (m,n) 的矩阵变成了 (n,m)，本该是列向量却是一维数组。

所以调试第一件事永远是打印 shape。

逐元素相乘 和 点积

最容易混的一对：

a = np.array([1, 2, 3])
b = np.array([4, 5, 6])

a * b          # array([ 4, 10, 18])   对应位置各乘各的，结果还是向量
a @ b          # 32                    1*4 + 2*5 + 3*6，结果是一个数
np.dot(a, b)   # 32                    和 @ 完全一样
运算符名字结果
*逐元素乘 element-wise向量
@矩阵乘 / 点积一维时是标量
np.dot同 @同 @

模型 w⊤x 用的是后者。

用点积算一遍模型

w = np.array([2.8, 0.5, -1.2, 8.0, -0.02])   # 面积 楼层 房龄 卧室 地铁
x = np.array([100,   12,   3,   3,  400])
b = 40

f = w @ x + b        # 338.4

同样一次预测，循环要五行，点积一行，还快几十倍。

广播

形状不同的数组做运算时，numpy 会自动把小的"铺开"：

a = np.array([1, 2, 3])
a + 10     # array([11, 12, 13])   标量自动加到每个元素上
a * 2      # array([ 2,  4,  6])

这就是为什么 w⊤x+b 里的 +b 不用写循环——标量会自动加到每个样本上。

核心概念

概念内容
多元线性回归多个特征，模型仍是 w⊤x+b
特征向量 x一个样本的 n 个特征组成的向量
权重向量 w每个特征一个权重，它的正负号有实际含义
点积逐项相乘再求和，结果是一个数，写作 w⊤x 或 w @ x
线性的含义指对参数线性，不是"图像是直线"
向量化用数组整体运算代替 for 循环
为什么快连续内存 + BLAS + SIMD/多核/GPU 并行
numpy 的坑* 是逐元素乘，@ 才是点积；出错先看 shape
