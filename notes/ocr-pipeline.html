漫画 OCR 翻译管线：识别、分块、翻译、回填

一条一次跑完的 CLI 管线，输入一张漫画，输出一张已经换好文字的图。真正难的不是识别，是“把译文放回原来的位置而且看起来不别扭”——这一步吃掉了大半的代码量。本文按四段拆开，每段给输入输出与失败模式，然后说三个必须做的取舍。

SECTION 01

任务定义：为什么漫画比公文难

公文 OCR 的目标是“把字变成字符”，坐标只需粗略保真；漫画翻译的目标是“把字换成另一种字，还要看着像原图”。前者的误差可以用置信度容忍，后者的误差一像素就能看见。四个具体的难点，每一个都能在代码里找到对应的补丁：

  • 气泡——文字被包在圆形或不规则轮廓里，底色是白的，边框是画的一部分。擦字必须停在边框内侧，但 OCR 给的框是一个矩形或四点框，不会沿着轮廓走。所以 Erase 只能按框涂阈值 mask 再修复（change.py，318 行）。
  • 竖排——日文气泡里是竖排、从右往左读，中文译文通常横排。同一张图上两种方向都可能有，因此方向必须先判断再决定画法：block.py（147 行）用“框的高宽比中位数 > 1.5”判定整图竖排，结果写进每个块的 vertical 标记，供 Replace 选择画法。
  • 拟声词——手写体、艺术字、带透视旋转，识别置信度天然低于正文气泡。这类框要么识别不到（不擦不译，原样保留），要么被识别成一个奇怪的字串后翻成更奇怪的东西。
  • 字体——中文字符比西班牙语、英语字符更宽，同样字号放不下原文的框。所以回填不能按“字数 × 字号”估算，必须用真实字体的度量值逐字测量（change.py 的 _char_wrap）。

结论

这条管线的重心不在模型，而在“坐标的搬运”：识别给的框是 4 点、分块要的是矩形、擦除要的是二值 mask、回填要的是字号与折行。四段之间每一次坐标转换都可能丢信息，丢在哪里，后面就得用规则补回来。

SECTION 02

管线四段：输入、输出与各自的失败模式

主流程只有十几行（main.py，64 行）：识别 → 擦除 → 分块 → 切句 → 批量翻译 → 拼回块 → 回填 → 存盘。注意顺序里有一个容易忽略的点：擦除发生在分块之前，因为擦除只需要框，不需要段落。

① 识别 · read.py（43 行）

输入图片路径。输出四个量：boxes（每行文字一个四点框，转成 int32）、txts、scores、elapse。实现是把引擎参数外置成一份 YAML（配置路径写在构造器里），并先调用 onnxruntime.preload_dlls() 把推理后端依赖载入，避免在 Windows 上第一次推理时找不到动态库。

失败模式：小字号或低对比度的拟声词整条漏掉；艺术字被切成两半，得到两个都不完整的框。这两种失败不会报错，只会安静地少一行译文。

② 分块 · block.py（147 行）

输入识别给的框与文本。输出按阅读顺序排列的段落块 [{box, text, vertical}]。做法四步：先把四点框压成轴对齐矩形；再两两判断“是否同段”；用并查集把框归组；最后组内排序拼字、组间按阅读顺序排。

“是否同段”不是学习出来的，是两条几何判据：竖排时看垂直重叠比例 ov_ratio ≥ 0.5 且水平间距 ≤ 1.5 × min(ha, hb)；横排时看水平重叠比例 ov_ratio ≥ 0.3 且垂直间距 ≤ 1.8 × 平均行高。阈值写死，所以它对排版风格很敏感。

失败模式：两个挨得近的气泡被并成一段，译文于是跨气泡；或者拟声词恰好落在判据范围内，被吞进对话里一起翻译。第一种会让回填时文字撑满一个跨越两气泡的大框。

③ 翻译 · trans.py（132 行）与 units.py（59 行）

输入块文本。输出与块数等长的译文列表。中间多了一层 units：先把每块按句末标点切句，单句超过 1,500 字符再按逗号分号兜底切，切完的行拼成一次请求发出去；返回后按 block_idx 归位到原块。

失败模式：接口可能一行对一行返回，也可能把整段译文揉成一条返回。后者如果直接按序对齐，第 2 块之后全部错位——这类错误在成品图上看不出来（文字都在框里），但内容全错了。所以 trans.py 写了三条对齐策略，见 §3。

④ 回填 · change.py（318 行）

输入原图 + 块坐标 + 每块译文。输出一张新图。两步：Erase 按所有识别框涂二值 mask、膨胀 5×5 后做 TELEA 修复（修复半径 3，写在 config.py 的 inpaintRadius），结果写到输出图；Replace 再逐个块二分字号、按字符折行、按背景亮度选黑字或白字画上去。

失败模式：修复半径偏大时，白底气泡会留下灰色块；偏小时，笔画残留会变成脏点。字体缺失时会降级到默认位图字体，中文全部变成方框。

四段的输入输出与失败模式（行数为 wc -l 实测）

SECTION 03

代码走读：三段真正在解决问题的片段

① 切句与归位：为什么翻译的单位不是“块”

整段丢给翻译接口，得到的是一整段译文：如果它比原文长，回填时字号会被压到很小；接口也可能把两句话合成一句，再想拆回原块就没依据了。把单位降成句子，一是长度可控，二是每句都带着 block_idx，回来后一定能拼回原块——即使某一句翻译失败，也能退回原文而不破坏结构。

python · units.py 切句与归位 
def _split_sentences(text):
    """按句末标点切句（标点保留在句尾）。
    (?![0-9]) 防止把 3.14 / v1.2 的数字点当句号切"""
    parts = re.split(r"(?<=[。！？.!?])(?![0-9])", text)
    return [p.strip() for p in parts if p.strip()]


def _chunk_long(sent, max_len=1500):
    """单句超长（>1500 字符）时按逗号/分号兜底再切，防止接口单行超限"""
    if len(sent) <= max_len:
        return [sent]
    parts = re.split(r"(?<=[,，;；])", sent)
    out, cur = [], ""
    for p in parts:
        if cur and len(cur) + len(p) > max_len:
            out.append(cur)
            cur = p
        else:
            cur += p
    if cur.strip():
        out.append(cur)
    return out


def regroup_blocks(units, translated, n_blocks):
    """输出长度 = n_blocks，每块拼成一段；翻译失败则保留原文"""
    holder = {}
    for u, t in zip(units, translated):
        holder.setdefault(u["block_idx"], []).append(t if t else u["text"])
    return ["".join(holder.get(i, [])) for i in range(n_blocks)]

units.py 全文 59 行。第二个正则的 (?![0-9]) 是踩过坑之后加的：没有它，"v1.2" 会在小数点处被切成两段。

② 字号自适配：用字体度量而不是估算法

回填最直接的做法是“字数 × 字号 ≈ 框宽”，中英混排时一定会错，因为每个字形的宽度不一样。这里改成两级搜索：外层对字号做二分，内层用 draw.textlength 逐字符累加折行。理由是单调性——字号越大，每行装的字越少、行数越多、行高越大，总高度单调上升，所以“总高 ≤ 框高”的最大字号可以二分求。

python · change.py 字号二分 + 折行 
    def _char_wrap(self, text, font, draw, max_w):
        """按字符贪心折行：中文没有空格可作断点，只能逐字试"""
        lines, cur = [], ""
        for ch in text:
            if draw.textlength(cur + ch, font=font) <= max_w or not cur:
                cur += ch
            else:
                lines.append(cur)
                cur = ch
        if cur:
            lines.append(cur)
        return lines or [""]

    def _layout_horizontal(self, text, box_w, box_h, draw):
        lo, hi = 6, max(6, min(120, int(box_h)))      # 字号搜索 6px ~ 框高（封顶 120）
        best = None
        while lo <= hi:                                # 二分找最大可行字号
            mid = (lo + hi) // 2
            font = self._load_font(mid)
            asc, desc = font.getmetrics()              # 行高 = 上伸 + 下伸
            line_h = asc + desc
            lines = self._char_wrap(text, font, draw, box_w * 0.94)   # 留 6% 边距
            if lines and len(lines) * line_h <= box_h * 0.94:
                best = (mid, lines, line_h, asc)
                lo = mid + 1                           # 放得下 → 试更大
            else:
                hi = mid - 1                           # 放不下 → 缩小
        if best:
            return best
        font = self._load_font(6)                      # 兜底：6px 硬画
        asc, desc = font.getmetrics()
        return (6, self._char_wrap(text, font, draw, box_w * 0.94), asc + desc, asc)

change.py 的 Replace 类。字体路径来自配置，找不到时按一份备选列表逐个尝试，最后降级到 Pillow 默认字体。

③ 批量请求与三条对齐策略

逐条请求最稳，但一张图 20 个气泡就是 20 次网络往返。这里选择“多行拼成一次请求”，代价是必须自己处理返回条数。注释里写清了三种情况，代码就照这三种分支走——第三种是把前两条都放弃后的兜底。

python · trans.py 批量与对齐 
        is_batch = isinstance(text, list)
        lines = text if is_batch else [text]
        results = list(lines)                                   # 先存原文保底
        idxs = [i for i, t in enumerate(lines) if t.strip()]    # 非空行下标
        q_text = "\n".join(lines[i] for i in idxs)              # 多行拼成一次请求
        data = self._post(q_text)                               # 端点/密钥在外层配置，不在这里

        if data and "trans_result" in data:
            dsts = [item["dst"] for item in data["trans_result"]]
            if len(dsts) == len(idxs):                          # ① 一行一个译文 → 直接对齐
                for k, i in enumerate(idxs):
                    results[i] = dsts[k]
            else:
                parts = "\n".join(dsts).split("\n")             # ② 整段返回 → 按换行拆回
                if len(parts) == len(idxs):
                    for k, i in enumerate(idxs):
                        results[i] = parts[k]
                else:                                           # ③ 拆不开 → 逐条兜底
                    for k, i in enumerate(idxs):
                        one = self._translate_one(lines[i])
                        results[i] = one if one else lines[i]

最坏情况退化为 N 次单条请求，速度变慢但不错位；单条请求失败时保留原文，成品图不会缺字。

SECTION 04

三个真实取舍

取舍一：整页翻译 vs 分块翻译

整页一次请求，上下文完整，指代、语气、上下句衔接都能被模型看到；但它返回的是一整段文本，与 OCR 的块没有对应关系，回填就无处落地。分块能对齐，代价是每块独立翻译：跨块的指代（“他”、“那家伙”）必然丢，“这是……”这种被气泡切断的长句也会各自成句。代码选了分块，并把损失写进 units.py 的 docstring 里——承认它是取舍，不是没想到。

取舍二：缩放回填 vs 直接绘制

缩放回填指把原文区域擦干净，再按框二分字号重新绘制文字。好处是字形锐利、可换字、可改行距，尺寸随框自适应；代价是字号与原文不一致，长译文会被压成很小的字，跟原图的字重对不上。直接绘制的替代方案是把译文渲染成位图再贴回框内（保留原始字重与倾斜），但那需要另一套字库和描边处理，且擦除后仍要处理底色。当前实现选前者的理由是：它只有一套坐标系，出错时能定位到“这块字号算错了”。

取舍三：批量请求 vs 逐条重试

批量省请求数与时间，但一次失败影响整批；逐条重试稳，但一张图 20 次往返，加上失败重试的等待，交互体验崩掉。当前做法是“批量优先 + 条数不符就降级逐条”：正常情况下一次请求，异常时自动退化。这个取舍的关键判据不是速度，而是错位比慢更贵——错位在成品图上看不出来。

一句结论

三个取舍都指向同一件事：把不可见的错误变成可见的慢。错位、字号过小、修复残留，这三类问题在缩略图上都看不出来，所以宁可让管线在某些图上明显变慢，也不让它安静地出一张错的图。

SECTION 05

已知缺陷与下一步

  • 四点框被压成矩形：block.py 的 to_rect 取四个顶点的外接矩形，倾斜的文字框会被放大，Erase 于是多擦了一圈。下一步：保留原始四点做多边形 mask（fillPoly），矩形只用于排版计算。
  • 修复会动到气泡边框：TELEA 用邻域像素补，白底气泡里擦掉文字后可能出现浅灰块，靠边框的位置还会影响到线稿。下一步：先按框内主色填一层纯色底，再只对残余笔画做小半径修复。
  • 翻译单位是句子，不是对话：跨句指代无法还原，被气泡切断的长句各自成句。下一步：把同一气泡内相邻块拼成上下文再翻，同时保留 block_idx 映射以便回填。
  • 字体依赖系统：找不到配置里的字体就逐个试备选，最后降级到位图默认字体，中文会变方框。下一步：字体随项目分发，启动时校验一次并在缺失时直接报错，而不是安静降级。
  • 没有测试：切句正则、regroup_blocks 的归位、字号二分的单调性，目前都靠人工看过成品图确认。下一步：给这三个纯函数各写一组断言，把“3.14 不被切开”“条数不符时不错位”这类约束钉住。
  • 端到端依赖密钥：config.py 在缺少环境变量时直接以 SystemExit 退出，因此 CI 里跑不了整条链路。下一步：把翻译层抽象成接口，测试用本地桩替换。
  • 调试输出留在主流程：main.py 末尾会把整份框、块、译文列表都 print 出来，一张图几百行输出。下一步：改成按需开关的日志级别。

这七条里，前两条是“需要重写坐标处理”，中间三条是“需要一层新的抽象”，后两条是“删代码就能解决”。按这个顺序修，是因为前两条直接影响成品质量，后两条只影响开发体验。

SECTION 06

术语表

气泡 Balloon / Speech Bubble 漫画里承载台词的封闭区域；擦字时不能越过后面的边框。
竖排阅读 Vertical Text 自上而下成列、列从右往左；代码用框的高宽比中位数判定整图方向。
拟声词 Onomatopoeia 手写、变形、带透视的字，识别置信度通常低于正文气泡。
版面分块 Layout Blocking 把相邻的文字行按几何关系合成段落块，一个块对应一个译文落点。
并查集 Union-Find block.py 用它把两两判定为同段的框合并成组，路径压缩两行循环。
四点框 Quad Box OCR 输出的四边形坐标；压成轴对齐矩形会丢掉旋转角。
图像修复 Inpainting (TELEA) 按邻域像素补洞的算法；半径越大越平但越容易糊掉细节。
膨胀 Dilation 把二值 mask 向外扩大，用来覆盖抗锯齿边缘的残余笔画。
字符折行 Character Wrapping 中文没有空格断点，只能逐字符累加真实宽度；英文会退化为逐字断。
字号二分 Binary Search Sizing 利用“总高随字号单调上升”求最大可行字号，区间 6px 到框高（封顶 120）。
对齐错位 Alignment Drift 批量请求返回条数与输入不等时，按序对齐会让后面的译文整体错一格。
