注意力机制：把“一个定长向量”拆成“每步现算的加权和”

一条从 Seq2Seq 的两个结构性缺陷出发的路线：打分 → softmax → 加权求和 → 拼接；然后是把同一个公式拆成多个头、把顺序信息手工注入。全文的公式、对比点与代码都以源笔记为据，源笔记里出现过的段落标注了行号。

SECTION 01

为什么需要注意力：Seq2Seq 的两个具体缺陷

先看 Seq2Seq 的骨架：编码器把源句 x₁ … x_N 读成一个固定长度的向量 c，解码器只拿 c 和上一步的输出生成目标词。缺陷不在于“RNN 不好”，而在于 c 的形状被写死在模型结构里。

缺陷一：固定长度向量压不住长句

不管源句是 5 个词还是 60 个词，编码器的输出永远是 H 维。信息量被压成常数，句子越长，每一步 c 要承担的东西越多，靠前的词在梯度上传到解码器时已经被稀释。源笔记把这一节写成“长句语义消失”，并给了可验证的读法：同一套超参、只改句长，看准确率随长度的分布——源文件 §1.2（第 90 行）。

缺陷二：对齐关系无处安放

解码第 t 步时，模型本应“看向”源句里对应的那个词；但在纯 Seq2Seq 里，这个“看向”没有任何变量可以表示——它只能隐式地存在于 c 里，而 c 是不可微的常量。语序调换（中文“五月十二日”对英文"12 May"）尤其吃亏，因为模型没有机制让第 t 步专门去取第 i 个源词的信息。源文件 §1.3（第 122 行）。

注意力的两刀切在这里：把常数 c 换成每一步现算的 c_t，并让 c_t 成为“源句所有位置向量的加权和”——权重就是可学习的对齐概率。源文件 §4.1 结尾有一句话概括得最准：对比无注意力的 Seq2Seq，唯一的变化就是把常数 c 换成每一步现算的 c_t。

取舍

注意力不是新增一层网络，而是把“取哪里的信息”从结构假设改成了可学习权重。代价是每步要算 n_k 个分数，训练变慢；收益是长句不再被一个定长向量卡住，并且顺带拿到了对齐矩阵。

SECTION 02

通用公式四步：打分 → softmax → 加权求和 → 拼接

给定 Q ∈ R^(n_q×d_k)、K ∈ R^(n_k×d_k)、V ∈ R^(n_k×d_v)，所有注意力变体都能塞进这四步（源文件 §3.1）：

① 打分　S = Q·Kᵀ / √d_k　　→ (n_q × n_k)
② 屏蔽　S = mask(S)　　→ 不该看的位置填 -1e9
③ 归一化　A = softmax(S, dim=-1)　　→ 每一行和为 1
④ 加权求和　O = A·V　　→ (n_q × d_v)

Q / K / V 各自是什么

  • Query——“我要找什么”。解码第 t 步时，它由当前解码状态投影而来；在 self-attention 里，它由本层输入投影而来。长度 n_q 决定输出的长度。
  • Key——“我能被什么样的 query 匹配”。它和 query 做内积，得到分数矩阵；只有 key 和 query 在同一空间里比，内积才有意义。
  • Value——“被匹配上之后我交出什么”。它不参与打分，只被加权求和；这也是为什么 d_k 和 d_v 可以不等。

三条必须记住的性质（源文件 §3.1 原文列出）：A 的每一行和为 1，是概率分布，可以算熵做诊断；输出长度 = query 长度 n_q，输出维度 = value 维度 d_v，n_k 只影响中间的分数矩阵；Q / K / V 长度可以完全不同——这正是 cross-attention 能“源句长度 → 目标句长度”的原因。

为什么要除以 √d_k

内积的方差随维度线性增长：d_k 越大，分数越容易拉开，softmax 被推到接近 one-hot，梯度接近 0。除以 √d_k 是把方差拉回 1 的最小改动，也让“点积”这种零参数的打分函数在大维度下重新可用。历史上 Bahdanau 用加性打分、直到缩放点积出现，很大程度就是这个数值问题（源文件 §3.3）。

五种打分函数，现在只剩两种在用

源文件 §3.2 的对照表：维度要求与今天的用途

选择的判据是纯工程的：数据大、维度高就用 scaled dot-product，它没有额外参数、能直接吃 GPU 的矩阵乘核；维度小、数据少、需要不同维度之间对齐才考虑加性，但它吃不到 GEMM 优化，长序列上慢一个量级。

SECTION 03

Bahdanau 与 Luong：只差一个顺序，训练动态就变了

Bahdanau 的四步写成公式是这样（源文件 §4.1）：

① 打分　e(t,i) = vᵀ·tanh(W_s·s(t-1) + W_h·h_i)　　i = 1…T
② 归一化　α(t,i) = exp(e(t,i)) / Σ_j exp(e(t,j))
③ 加权求和　c_t = Σ_i α(t,i)·h_i
④ 解码　s_t = GRU([y(t-1); c_t], s(t-1))　·　o_t = W_o[s_t; c_t] + b_o

叫“加性”是因为它先加再 tanh：W_s s(t-1) 和 W_h h_i 形状相同，逐元素相加后过 tanh，再由 v 投成标量。其中 W_s 是 d_a × H，W_h 是 d_a × 2H——2H 是因为 h_i 是双向 RNN 前向与后向输出的拼接，天然带着第 i 个词左右两边的上下文。

Luong 的改动只有两处：打分用当前状态 s_t 而不是上一步的 s(t-1)；打分函数给了 dot / general / concat 三个变体。它额外引入 input feeding——把上一步的注意力向量拼到当前输入，让模型知道自己上一眼看的是什么。

四个维度的对比（源文件 §4.4 的表，加了对“方向”的补充说明）
对比项Bahdanau (2015)Luong (2015)
打分用的状态上一步 s(t-1)：先对齐，再走 RNN当前 s_t：先走 RNN，再对齐
打分函数加性 vᵀtanh(W_s s + W_h h)，多一次 tanh 与两次投影dot / general / concat 三选一，dot 最省，纯矩阵乘

拼接方式c_t 与上一步输出嵌入拼成 [y(t-1); c_t] 喂给 GRU，输出层再拼一次 [s_t; c_t]input feeding：上一步的注意力向量拼进当前输入；另有 global / local 两种取范围

这个顺序差别不是风格问题：先用旧状态对齐，意味着“注意力是我这一步的输入”；先用新状态对齐，意味着“注意力是我这一步输出之后的解释”。Transformer 解码器选了前者——先做 self-attention 得到当前表示，再拿它当 query 去做 cross-attention（源文件 §4.4 末段）。

顺带一个实现细节：Bahdanau 里 h_i 既参与打分（相当于 key）又直接参与加权求和（相当于 value），所以很多实现干脆让 K = V。现代做法给 K、V 各自一个投影，因为“像不像我”和“该给我什么”本来可以是两件事（源文件 §4.2）。

SECTION 04

Self-Attention 与 Multi-Head：一个 softmax 装不下多种关系

从 cross-attention 到 self-attention，改的只有一件事：Q / K / V 从哪来。cross 里 Q 来自解码器、K 和 V 来自编码器；self 里三者都来自同一层输入，于是“每个位置去问所有位置（包括自己）”。这带来两个直接后果：可以并行（不依赖时间步），以及——完全不知道顺序。

它真的不知道顺序

严格说，self-attention 是置换等变的：把输入序列打乱，输出也只被打乱，内容不变。因为加权求和 Σ_j α(ij)·v_j 对下标 j 没有任何偏好，只按内容算相似度。源文件 §5.5 给的例子是“狗咬人”与“人咬狗”——两句话在纯 self-attention 看来内容一样。这就是 §5 存在的唯一理由。

python · 单头注意力全部代码 
def scaled_dot_product_attention(q, k, v, mask=None):
    # q: (B, n_q, d_k)   k, v: (B, n_k, d_k / d_v)
    scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))   # (B, n_q, n_k)
    if mask is not None:
        scores = scores.masked_fill(mask, -1e9)
    attn = torch.softmax(scores, dim=-1)                       # 每行和为 1
    return attn @ v, attn

源文件 §5.6（第 611 行）。q @ k.transpose(-2,-1) 的含义是：两个向量的相似度 = 内积。

为什么要多个头

单个注意力只能产生一种加权方式：一个 softmax 分布。但一句话里同时存在多重关系——动词对主语、代词对先行词、相邻词、主题词。一个分布没法同时表达：它给 "it → animal" 0.55，就很难再给 "it → was" 0.5，因为一行权重和必须为 1。

多头就是解这个约束：把表示维拆成 h 份，每一份独立做一次注意力，各管一种关系。这就是“子空间假设”——每个头在自己的低维子空间里量相似度，比在一个高维空间里挤一个分布更容易分工。

head_i = Attention(Q·W_i^Q, K·W_i^K, V·W_i^V)　　d_k = d_v = d / h
MultiHead(Q,K,V) = Concat(head_1 … head_h)·W^O

关键是 d_k = d_v = d/h：多头不增加总计算量，只是把一个大注意力拆成 h 个小注意力并行。源文件 §6.4 拿 d=512, h=8, d_k=64 算过账：W_Q / W_K / W_V 各 512²=262,144，W_O 同样，单个多头注意力总计 4d² = 1,048,576 个参数；计算量 h × O(n²·d/h) = O(n²·d)，与单头同阶。

形状账：多头实现最容易写错的地方

源文件 §6.3 的形状表，写代码前先对一遍
步骤代码形状
投影w_q(x)(B, n, d)
拆头.view(B, n, h, d_k).transpose(1, 2)(B, h, n, d_k)
打分q @ k.transpose(-2,-1) / √d_k(B, h, n_q, n_k)

两个经典 bug 都出自这张表：view 放在 transpose 之后，转置过的张量内存不连续，要么报错要么悄悄读错数据，必须先 .contiguous() 或改用 reshape；把拆头写成 .view(B, h, n, d_k) 而不是 .view(B, n, h, d_k).transpose(1, 2)，两者元素顺序不同，模型能跑但学不好，而且不报错——这是最难查的一类 bug（源文件 §6.3）。

SECTION 05

位置编码：注意力本身没有顺序，只能手工注进去

既然 self-attention 对下标没有偏好，位置信息必须由外部提供。论文的原版做法是正弦编码：偶数维用 sin、奇数维用 cos，波长从 2π 到 10000·2π 呈几何级数分布——像把秒针、分针、时针叠在一起，各自记录不同粒度的位置（源文件 §7.2）。

PE(pos, 2i)　 = sin( pos / 10000^(2i/d) )
PE(pos, 2i+1) = cos( pos / 10000^(2i/d) )　　d = 模型维，i = 维度下标

为什么不用直接写 pos？三个理由，都能验证：

  • 数值有界：sin / cos 恒在 [-1, 1]，句子再长也不会爆；直接写 pos 的话第 1000 个位置的取值是 1000，会把词向量的尺度彻底淹没。
  • 能表达相对位置：对任意固定偏移 k，PE(pos+k) 都是 PE(pos) 的一个线性变换（旋转矩阵），于是“位置差 5”这个信息能被后续线性层直接学出来。[sin(ω(pos+k)); cos(ω(pos+k))] = [[cos ωk, sin ωk], [−sin ωk, cos ωk]]·[sin(ω·pos); cos(ω·pos)]
  • 可以外推：函数形式固定，理论上比“学一张长度 512 的 embedding 表”更能覆盖没见过的长度（实践中外推能力也有限，所以后来有了 RoPE / ALiBi 这一代方案）。

用法是相加而不是拼接：x_i = Embed(w_i)·√d + PE_i。乘 √d 是因为词嵌入初始化后的尺度约 1/√d 量级，要放大到和 PE 同一量级，否则位置信号会盖过词义。论文自己对比过：正弦编码与可学习的位置 embedding 效果几乎一样，选正弦是因为它不增加参数、且理论上能外推到更长序列。

SECTION 06

一个可跑的最小实现：正弦编码 + 多头注意力

下面这段只依赖 torch，形状按 §4 的表来，末尾三行是自检：输出形状是否为 (2, 6, 512)、注意力是否 (2, 8, 6, 6)、每一行权重和是否为 1。跑通它，再去看 §7 的坑清单。

python · 最小实现 
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


def scaled_dot_product_attention(q, k, v, mask=None):
    scores = q @ k.transpose(-2, -1) / math.sqrt(q.size(-1))
    if mask is not None:                      # mask 里 True = 屏蔽
        scores = scores.masked_fill(mask, -1e9)
    attn = F.softmax(scores, dim=-1)          # 每一行和为 1
    return attn @ v, attn


class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_head):
        super().__init__()
        assert d_model % n_head == 0
        self.h = n_head
        self.d_k = d_model // n_head          # d_k = d_v = d / h
        self.w_q = nn.Linear(d_model, d_model)
        self.w_k = nn.Linear(d_model, d_model)
        self.w_v = nn.Linear(d_model, d_model)
        self.w_o = nn.Linear(d_model, d_model)

    def forward(self, x, mask=None):
        B, n, d = x.shape
        # 先 view 再 transpose：反过来会读错数据
        q = self.w_q(x).view(B, n, self.h, self.d_k).transpose(1, 2)
        k = self.w_k(x).view(B, n, self.h, self.d_k).transpose(1, 2)
        v = self.w_v(x).view(B, n, self.h, self.d_k).transpose(1, 2)
        out, attn = scaled_dot_product_attention(q, k, v, mask)
        # 并头前必须 contiguous，否则 view 会报错
        out = out.transpose(1, 2).contiguous().view(B, n, d)
        return self.w_o(out), attn


class PositionalEncoding(nn.Module):
    def __init__(self, d_model, max_len=512):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        pos = torch.arange(max_len, dtype=torch.float).unsqueeze(1)
        div = torch.exp(torch.arange(0, d_model, 2, dtype=torch.float)
                        * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(pos * div)
        pe[:, 1::2] = torch.cos(pos * div)
        self.register_buffer("pe", pe)

    def forward(self, x):
        # 相加，且把词嵌入放大到与 PE 同一量级
        return x * math.sqrt(x.size(-1)) + self.pe[: x.size(1)]


if __name__ == "__main__":
    x = torch.randn(2, 6, 512)
    mha = MultiHeadAttention(d_model=512, n_head=8)
    y, a = mha(x)
    print(y.shape)        # torch.Size([2, 6, 512])
    print(a.shape)        # torch.Size([2, 8, 6, 6])
    print(a[0, 0, 0].sum())   # tensor(1.0000)
    z = PositionalEncoding(512)(x)
    print(z[0, 3, :4])    # 前四维都落在 [-1, 1] 附近

参数量核对：4 × 512² = 1,048,576，与源文件 §6.4 的表一致。

SECTION 07

常见坑：一句因、一句果

坑 01 · mask 语义写反

因：masked_fill(mask, -1e9) 里 True 表示“填掉”，而很多框架的 padding mask 是 True 表示“保留”。果：训练 loss 照常下降，但推理时模型看到了未来的 token，或把 pad 位当成了上下文。

坑 02 · transpose 之后用 view

因：转置后的张量在内存里不连续，view 要么直接报错，要么按错的顺序读数据。果：并头之后的表示与拆头时不对齐，模型能跑但效果莫名其妙地差。

坑 03 · 忘了除以 √d_k

因：内积方差随维度线性放大，分数差值被拉到几十量级。果：softmax 输出接近 one-hot，梯度接近 0，训练在前期就停住。

坑 04 · 位置编码用了拼接但没改维度

因：论文的做法是相加，d_model 不变；改成拼接后输入维度变成 2d。果：下游第一层线性层的权重对不上，要么形状报错，要么静默地只吃了一半特征。

坑 05 · 多头拆头写了 .view(B, h, n, d_k)

因：这个形状的元素顺序与 .view(B, n, h, d_k).transpose(1, 2) 不同。果：不报错、能收敛，但每个头拿到的是被时间维和头维交错切开的数据，等于把头随机混合了（源文件 §6.3 点名的第二类 bug）。

SECTION 08

术语表

查询 / 键 / 值 Query / Key / Value Q 找什么、K 能被什么匹配、V 交出什么；只有 Q 与 K 需要同维度。
缩放点积注意力 Scaled Dot-Product Attention 打分用 qᵀk 再除以 √d_k，零参数，Transformer 全系统一形式。
加性注意力 Additive Attention 先投影相加、过 tanh、再投成标量；Bahdanau 用的就是它。
交叉注意力 Cross-Attention Q 来自解码器、K 和 V 来自编码器；输出长度由 Q 决定。
自注意力 Self-Attention Q / K / V 同源，等价于每个位置去问所有位置，可并行。
多头注意力 Multi-Head Attention 拆 h 份、每份 d_k = d/h，各做一次注意力后拼接再投影。
置换等变 Permutation Equivariance 打乱输入，输出只被打乱、内容不变；这正是 self-attention 不知道顺序的形式化说法。
位置编码 Positional Encoding 把位置信息注入表示；论文用 sin / cos 直接相加到词嵌入上。
屏蔽 Mask 在 softmax 之前把不该看的位置填 -1e9；padding mask 与 causal mask 语义要分清。
软对齐 Soft Alignment 把所有解码步的 α 拼成矩阵得到对齐热图，是模型内部中间量，不是事后解释。
输入反馈 Input Feeding Luong 的技巧：把上一步的注意力向量拼进当前输入，让模型知道自己上一眼看了哪。
